# Pi Desktop Mate — 설계 문서 (v0.1)

> **데이터 경계와 원격 실행 방향은 [세 앱의 역할과 데이터 경계](DESIGN-APPS.md)를 따른다.** 원격 실행기(D5)는 [Mate 원격 실행기](DESIGN-MATE-REMOTE.md)에 따로 적는다. Mate는 개인화된 데이터를 능동적으로 처리하는 Pi 기반 비서다.
>
> 관련 문서: [Pi Desktop 설계](DESIGN.md), [Pi Desktop Agent 설계](DESIGN-AGENT.md), [개발 방식](CONTRIBUTING.md). 사용법은 [apps/mate/README.md](../apps/mate/README.md)

Pi Desktop Mate는 **사용자가 묻기 전에 Pi가 스스로 살펴보고, 알릴 것은 알리고, 할 일은 허락을 받은 뒤 하는** 능동형 코딩 동료다.
Pi Desktop(설치된 Pi의 GUI)과 Pi Desktop Agent(채팅형 데스크톱 에이전트)와는 **별도 앱**이다.
Pi를 포크하지 않는다는 원칙은 같다. Pi는 그대로 두고, 확장(`mate-kit`)과 상주 실행기(`mate-runner`), 앱(`apps/mate`)을 새로 만든다.

## 0. 확정된 결정

| 항목 | 결정 |
|---|---|
| 저장소 | pi-desktop 모노레포에 추가. `apps/mate`(Electron 앱) + `packages/mate-kit`(Pi 확장) + `packages/mate-runner`(상주 실행기) |
| 기존 코드와의 분리 | `apps/desktop`, `packages/host-agent`, 루트 README, `DESIGN.md`는 **고치지 않는다**. host-agent의 Pi 찾기·데몬 띄우기 코드는 읽기만 하고 번들에 넣어 쓴다. 겹치는 파일은 `package-lock.json`뿐 |
| Pi Desktop Agent와의 분리 | 이름(`mate`)·폴더·데이터 홈·포트·태그를 모두 나눈다 (§7). 작업은 별도 worktree(`../pi-desktop-mate`)의 `feat/mate-*` 브랜치에서 한다 |
| 메타 파일 | **`~/.pi-desktop-mate/`** 에 따로 둔다 (`MATE_HOME`으로 바꿈). Pi 설치본·로그인·모델·설정(`~/.pi/agent`)만 같이 쓴다 (API 키를 다시 넣지 않도록). Pi를 띄울 때 `-ns -np -ne -nc`로 Pi Desktop의 스킬·프롬프트·확장·사용자 지침이 임무에 끼어들지 않게 한다 (DESIGN-APPS.md §3.1) |
| 기본 모델 | `anthropic/claude-haiku-5-5` (설정에서 목록으로 바꿈. "Pi 기본 모델 따르기"를 고르면 `--model`을 넘기지 않아 Pi Desktop에서 바꾼 기본 모델을 따름. 임무마다 덮어쓸 수 있음) |
| 알림 | 인박스에 쌓여 앱을 켰을 때 본다. 앱 창을 보고 있지 않으면 PC 알림(OS 알림)으로 대화 답·질문(승인 요청)·임무 결과·새 제안을 알린다(설정에서 끔, 앱의 main이 실행기의 "바뀜" 알림마다 overview를 견줘 새것만, 처음 읽은 것은 기준만). 휴대폰(텔레그램)을 연결하면 바로 알림을 받고 버튼으로 처리·지시할 수 있다 (§12) |
| 릴리스 | Pi Desktop의 `v*`, Agent의 `agent-v*`와 섞지 않고 `mate-v*` 태그와 별도 워크플로(`.github/workflows/mate-release.yml`)를 쓴다. Mate 릴리스는 GitHub에서 **Latest로 표시하지 않는다** (Pi Desktop 자동 업데이트가 Latest 릴리스를 보기 때문). Mate 자동 업데이트는 §11 |

## 1. 참고한 제품

2026년 9~10월에 나온 능동형(proactive) 에이전트 세 가지에서 공통점을 뽑았다. 출시 직후의 보도와 리뷰를 바탕으로 했으므로 세부는 바뀔 수 있다.

| | Meta Muse (9월) | OpenAI Dots (9~10월) | Claude Duet (10월, 미리보기) |
|---|---|---|---|
| 도는 곳 | 앱을 닫아도 계속 일함 | 에이전트마다 클라우드 컴퓨터 | 전용 클라우드 VM·브라우저 |
| 먼저 말 거는 방식 | 목표와 관련된 정보가 바뀌면 계획 변경 제안, 일정·마감 알림 | 놀 때 연결된 앱을 훑어 도울 거리를 찾음 | 아침 요약, 몇 시간마다 연결된 계정 확인 |
| 권한 | 메일 보내기·예약·결제까지 | 훑을 때는 **읽기 전용** | 보내기·결제·서명·삭제 전 **승인 요청** |

공통점:

1. **항상 켜져 있다.** 앱을 닫아도 정해진 때에 일한다.
2. **계기(trigger)가 있다.** 시간표, 변화 감지, 주기적 훑기.
3. **살펴보기는 읽기 전용, 행동은 승인 뒤.** 위험한 일은 아예 막는다.
4. **결과는 알림·제안으로 돌아온다.** 사용자는 받아들이거나 버린다.
5. **비용·소음·보안이 핵심 위험이다.**

Mate의 "할 일"은 개인 비서가 아니라 **코딩 작업 공간**이다: 아침 브리핑(git·PR·CI 상태), 테스트 감시, CI·리뷰 대응, 의존성·보안 점검, 원격 서버 지킴이.

## 2. 구조

```
┌ apps/mate (Electron) ──────────────────────────────────────┐
│ 인박스(제안·승인 대기) · 임무 목록 · 실행 기록 · 설정            │
│ Main: ~/.pi-desktop-mate 파일 읽기·쓰기·감시, 실행기 띄우기      │
└──────────────┬────────────────────────────────────────────┘
               │ 파일 (임무 JSON, 실행 요청, 인박스 JSONL, 상태)
┌──────────────▼──── mate-runner daemon (상주, 앱을 닫아도 돎) ┐
│ 시간표 확인(30초마다) · 실행 요청 처리 · 하루 횟수 제한            │
│   └ pi --mode json -e <mate-kit 확장> --tools <읽기 도구> ...   │
│        (실행마다 새 Pi 프로세스, 끝나면 종료)                    │
└────────────────────────────────────────────────────────────┘
```

### 2.1 Host Agent 데몬을 쓰지 않는 이유

처음 안(PROACTIVE-AGENTS 초안 B)은 Host Agent 데몬 안에 실행기를 넣는 것이었다. 별도 앱으로 바꾸면서 다음 이유로 **자체 실행기**를 둔다.

- Host Agent는 Pi Desktop의 것이다. 고치면 Pi Desktop 릴리스와 엮이고, 다른 세션(Agent)과도 겹친다.
- 백그라운드 실행은 "한 번 돌고 끝나는" 작업이라 `pi --mode json`(실행 후 종료)이 딱 맞는다. 세션 붙이기·저널·대기 다이얼로그가 필요 없다.
- 승인을 "열린 세션이 기다리는 다이얼로그"로 하지 않는다 (§4). 앱이 몇 시간 꺼져 있어도 Pi 프로세스를 붙잡아 둘 필요가 없다.

Pi 찾기(`locatePi`)와 Windows에서 부모 핸들을 물려받지 않게 데몬 띄우기(`spawnDaemon`)는 host-agent 소스를 그대로 번들해 쓴다(수정 없음).

### 2.2 앱과 실행기 사이

소켓 대신 **파일**로 주고받는다. 같은 사용자의 홈 폴더라 인증이 따로 필요 없고, 앱이 꺼져 있어도 상태가 남는다.

| 파일 | 쓰는 쪽 | 읽는 쪽 |
|---|---|---|
| `config.json` (기본 모델, 일시 정지, 하루 실행 상한) | 앱 | 실행기 |
| `duties/<id>.json` (임무) | 앱 | 실행기 |
| `requests/<시각>-<id>.json` ("지금 실행") | 앱 | 실행기 (처리 후 지움) |
| `state.json` (임무별 마지막 실행, 오늘 실행 수, 지금 도는 실행) | 실행기 | 앱 |
| `runs/<runId>.json` (실행 기록: 상태·요약·비용·세션 파일) | 실행기 | 앱 |
| `inbox.jsonl` (제안, 추가만 함) | mate-kit 확장 | 앱 |
| `inbox-state.json` (제안별 받아들임·버림) | 앱 | 앱·실행기 |
| `sessions/` (실행마다의 Pi 세션 JSONL) | Pi | 앱 (나중에 "세션 열기") |
| `run/mated.pid`, `run/mated.log` | 실행기 | 앱 |

인박스는 추가만 하는 JSONL과 상태 파일을 나눠, 확장의 추가와 앱의 상태 변경이 같은 파일을 동시에 고치지 않게 한다.
Pi 세션을 `~/.pi/agent/sessions`가 아니라 Mate 홈에 두는 것은 백그라운드 실행이 Pi Desktop·TUI의 세션 목록을 채우지 않게 하기 위해서다. 형식은 Pi 그대로다.

### 2.3 실행기 수명

- 앱이 켜질 때 실행기가 없으면 띄운다. 실행기는 앱을 닫아도 남아 시간표를 지킨다.
- 하나만 돈다(`run/mated.pid` + 프로세스 확인).
- 실행기가 꺼져 있던 동안 놓친 시간표는 **한 번만** 따라잡는다.
- **로그인할 때 실행기 시작**(설정, 설치본만): 로그인 항목이 앱을 `--mate-runner-only`로 띄워 창 없이 실행기만 확인하고 끝낸다.
  Windows·macOS는 Electron 로그인 항목(macOS는 `wasOpenedAtLogin`으로 구분), Linux는 `~/.config/autostart/pi-desktop-mate.desktop`. 끄면 PC를 다시 켠 뒤 앱을 한 번 열어야 실행기가 돈다.

## 3. 임무(Duty)

```json
{
  "id": "morning-brief",
  "name": "아침 브리핑",
  "enabled": true,
  "cwd": "C:/Users/me/my-project",
  "prompt": "git 상태, 열린 PR과 CI를 확인해 오늘 할 일을 3줄로 요약하라.",
  "profile": "propose",
  "trigger": { "kind": "daily", "time": "09:00", "weekdays": [1, 2, 3, 4, 5] },
  "model": "anthropic/claude-haiku-5-5",
  "timeoutSec": 300,
  "createdAt": 1793000000000
}
```

계기:

| 종류 | 언제 도나 | 단계 |
|---|---|---|
| `manual` | "지금 실행"으로만 | M1 |
| `interval` | N분마다 (최소 15분). 시간대(`from`~`to`, 자정을 넘어도 됨)와 요일을 정하면 그 안에서만 돌고, 시간대가 열리면 바로 한 번 돈다 (예: 낮 시간에만 매시간) | M1 |
| `daily` | 매일(또는 정한 요일) 정한 시각. 만든 시각 이전의 시간표는 따라잡지 않는다 | M1 |
| `git` | 새 커밋·브랜치 바뀜. 실행기가 확인할 때마다(30초) `git rev-parse`로 본다 | M2 |
| `files` | 작업 폴더의 파일 저장. `.git`·`node_modules`·빌드 결과는 빼고, 저장이 잠잠해진 뒤(기본 60초) 한 번 | M2 |
| `poll` | 읽기 명령 하나를 정한 간격(최소 15분)마다 돌려 출력이 바뀌면. 명령은 mate-guard 허용 목록을 통과해야 하고 `\|`·`&&`는 못 쓴다 | M2 |

변화 계기(`git`·`files`·`poll`)의 규칙:

- 처음 본 값은 **기준으로만** 삼는다. 임무를 만들거나 실행기를 다시 띄워도 바로 돌지 않는다.
  계기 종류·폴더·명령이 바뀌면 기준을 다시 잡는다.
- 한 번 돈 뒤 **쉬는 시간**(git·files 기본 15분, 최소 5분) 안에 생긴 변화는 모아 두었다가 쉬는 시간이 끝나면 한 번 돈다.
- 실행 기록에는 `reason: change`와 무엇이 바뀌었는지(`cause`, 예: "커밋 d287ceb (main)", "파일 2개 바뀜 (a.txt, c.txt)")를 남긴다.
  모델에게도 이 내용을 알려 바뀐 부분을 중심으로 보게 한다.
- 일시 정지·하루 상한 중에도 변화는 기록한다. 그래야 풀렸을 때 기준이 어긋나지 않는다.

세션 종료 계기(사용자가 Pi Desktop에서 작업을 마쳤을 때)는 Pi Desktop과 엮여야 하므로 미룬다.

## 4. 권한 단계와 승인

권한은 모델의 말이 아니라 **실행 인자와 확장 코드로** 강제한다.

| 단계 | 모델에 주는 도구 | 막는 것 |
|---|---|---|
| `observe` | read·grep·find·ls·bash | write·edit는 도구 목록에 아예 없음. bash는 허용 목록의 읽기 명령만(`mate-guard`) |
| `propose` (기본) | observe + `mate_propose` | 같음. 제안은 인박스에만 쌓인다 |
| `act` (고치기, M3) | propose + edit·write | write·edit는 작업 공간(worktree) 안만. bash는 같은 읽기 허용 목록이라 push·배포·삭제·설치는 못 한다 |
| 모든 단계 (D2.5) | + 임무가 고른 MCP 서버의 도구 | 처음 쓰는 MCP 도구는 막고 허용을 묻는다 (아래 "권한 요청"). 허용한 도구만 통과 |

- `--tools`로 도구 목록을 정하고(쓰기 도구는 선언조차 안 됨), `mate-guard` 확장이 `tool_call`에서 한 번 더 막는다.
- 스킬·프롬프트·MCP 서버는 Mate 홈(`skills/`, `prompts/`, `mcp.json`)의 것만 쓰고 임무마다 고른다 (DESIGN-APPS.md §3.4). 스킬은 지침일 뿐 권한을 넓히지 않는다.
  Pi security.md가 말하듯 확장 hook은 보안 경계가 아니다. 이 단계는 "실수로 손대지 않게"하는 장치다. act는 여기에 더해 사용자 폴더 대신 별도 worktree에서 돌고, 적용 전까지 사용자 폴더를 바꾸지 않는다.
- act의 쓰기 범위: Pi와 같이 `@`를 떼고 cwd 기준으로 풀어 작업 공간 안인지 본다. `~`(홈), 바깥, `.git` 안, 바깥을 가리키는 링크는 막는다.
- bash 허용 목록: `git status/log/diff/show/branch/remote -v`, `gh pr|run|issue view|list|checks|status`, `ls/cat/head/tail/wc/grep/rg/find`(쓰기 옵션 제외), `npm ls/outdated/view`, `node -v` 등. 파이프는 각 단계가 모두 허용될 때만, 리다이렉트(`>`)·명령 치환은 막는다.
- 읽은 내용(코드·이슈·로그) 속 지시는 데이터로만 다루라고 시스템 프롬프트에 넣는다.

**승인은 "대기하는 세션"이 아니라 "대기하는 인박스 항목"이다.** 앱이 꺼져 있는 동안 생긴 승인 건은 모두 인박스에 쌓이고,
사용자가 앱을 열어 받아들일 때 실제 행동이 일어난다. `act`(M3)는 이렇게 한다.

1. 실행기가 사용자 저장소 HEAD에서 **브랜치 없는(detached) worktree**를 Mate 홈 `worktrees/<runId>`에 만들고, 그 안(임무가 하위 폴더면 그 폴더)에서 Pi를 띄운다.
   브랜치·커밋을 만들지 않아 사용자 브랜치 목록과 커밋 훅을 건드리지 않는다. 사용자가 커밋하지 않은 변경은 작업 공간에 없다 (HEAD 기준). git 저장소가 아니면 실행하지 않는다.
2. 끝나면 변경(새 파일 포함)을 모아 "파일 N개 고침" 제안(stat·diff, 중요도 할 일)으로 인박스에 올린다. 변경이 없거나, 실패했거나, 같은 패치를 이미 올렸으면 작업 공간을 지운다.
3. **적용**: 작업 공간의 diff를 사용자 폴더에 **커밋하지 않은 변경**으로 적용한다(`git apply`, 먼저 `--check`). 그사이 같은 곳이 바뀌었으면 적용하지 않고 이유를 알린다. 커밋은 사용자가 한다.
   **버리기**: 작업 공간을 지운다. 두 동작 모두 Mate 홈 `worktrees/` 안의 작업 공간만 다룬다 (인박스 줄이 다른 폴더를 가리켜도 건드리지 않음).

**권한 요청 (막힌 명령)**: 임무가 읽기 전용 허용 목록에 없는 명령(예: HN API를 부르는 `curl`)을 쓰려다 막히면, 글로만 남기고 끝나지 않게 사용자에게 허용을 묻는다.

1. mate-guard는 그 명령을 막으면서 이름과 원래 명령을 `run/blocked/<runId>.jsonl`(`PI_DESKTOP_MATE_BLOCKED`)에 남긴다. 모델에게는 "허용을 요청해 두었으니 우회하지 말고 막힌 것을 요약에 적어라"고 알린다.
   허용을 묻는 것은 "목록에 없을 뿐인" 명령 이름만이다. 리다이렉트·명령 치환처럼 구조 때문에 막힌 것과, 쓰기 하위 명령이 있는 git·gh·npm은 묻지 않는다.
2. 실행이 끝나면 실행기가 아직 허용하지 않은 이름을 모아 대화에 질문을 남긴다 (`permission` 표시, 선택지 "허용하고 다시 실행"·"허용하지 않음"). 앱 대화 탭과 휴대폰에 버튼으로 뜬다. 답하지 않은 같은 질문은 하루 안에 다시 묻지 않는다.
3. 답은 모델을 거치지 않고 대화 담당이 바로 처리한다. 허용하면 임무의 `grants`에 이름을 더하고 다시 실행하며, 끝나면 결과를 그 출처로 알린다. 처음 답만 따른다. 예·아니요로 읽을 수 없는 답("왜 필요해?")은 모델이 받는다.
4. 다음 실행부터 mate-guard는 `grants`(`PI_DESKTOP_MATE_GRANTS`)의 명령도 통과시킨다. 그래도 리다이렉트·명령 치환은 막고, `curl`·`wget`은 파일 쓰기·데이터 보내기 옵션을 막아 읽어 오기만 하게 한다 (`wget`은 `-O-`로 화면에 받을 때만). 허용한 명령은 임무 고치기 화면에서 뺄 수 있다.
5. **MCP 도구도 같은 흐름이다 (D2.5).** Mate는 MCP 도구가 읽기인지 쓰기인지 알 수 없으므로, 임무가 고른 서버의 도구라도 `grants`에 없으면 막고 `mcp__<서버>__<도구>` 이름으로 기록한다. 질문에는 서버·도구 이름과 도구 설명을 보여 주고, 허용하면 그 도구만 `grants`에 더한다 (서버 전체를 한 번에 허용하지 않는다). 질문이 길어지지 않게 한 번에 묻는 도구는 다섯 개까지다.

## 5. 인박스

- `mate_propose` 입력: 제목, 요약, 상세(근거·파일·명령 출력, Markdown), 중요도(`info`·`warn`·`action`).
- 같은 임무에서 제목+요약이 같은 제안은 다시 알리지 않는다(해시로 중복 제거, 버린 것도 기억).
- 앱에서: **받아들이기**(M1은 "확인함" 표시, M3부터 적용), **버리기**. 안 본 제안 수를 배지로 보인다.
- **설치 제안 카드 (D2.5)**: 제안에 `install`이 붙으면 받아들이기가 "적용"이 되고, 실행기가 승인 뒤에 Mate 홈에 넣는다 (DESIGN-APPS.md §3.4).
  - 스킬 초안: `SKILL.md` 내용을 그대로 보이고, 적용하면 `skills/<이름>/`에 저장한다. 같은 이름이 있으면 덮어쓰지 않고 다시 묻는다.
  - MCP 서버 추가: 정해 둔 목록의 서버만. 띄우는 명령·접근하는 서비스·필요한 토큰을 보이고, 적용하면 `mcp.json`에 넣는다. 토큰은 사용자가 Mate의 MCP 탭에서 넣는다.
  - 다른 앱에서 복사: 원본 위치와 내용을 보이고, 적용하면 Mate 홈으로 복사한다. MCP 설정은 복사하지 않는다.
- 실행이 제안 없이 끝나면 마지막 답변을 실행 기록에 요약으로 남긴다.

## 6. 예산과 안전

- 전체 일시 정지, 하루 자동 실행 상한(시간표·변화 합계, 기본 20회), 실행 시간 제한(기본 300초, 넘으면 프로세스 종료).
- 실행은 한 번에 하나씩(비용·충돌 줄이기).
- 비용은 Pi의 메시지 `usage.cost`를 합쳐 실행 기록과 오늘 비용에 남긴다.
- **실행당 비용 상한**(설정 기본 $0.5, 임무마다 덮어씀, 0이면 없음): 넘으면 Pi를 끝내고 상태를 "비용 상한"으로 남긴다.
  메시지가 끝날 때마다 확인하므로 한 메시지만큼은 넘을 수 있다.
- 실행마다의 Pi 세션은 앱의 **세션 보기**로 읽을 수 있다. 무엇을 읽었고 어떤 명령이 막혔는지 확인하는 용도다 (Mate 홈 `sessions/` 안의 파일만 연다).

## 9. Pi 준비 (M4)

Mate는 Pi 설치·로그인·모델 관리 화면을 따로 만들지 않는다. 그 일은 Pi Desktop이 맡고, Mate는 상태를 알리고 Pi Desktop을 쉽게 설치·열게 돕는다.

- 실행기 `status` 명령이 Pi Desktop Host Agent의 `piStatus`·`listPiModels`를 수정 없이 번들해 읽기만 한다.
  Pi 설치(관리형·npm 전역)·버전, Windows Git Bash, 로그인한 프로바이더(이름만), `pi --list-models`의 모델, Pi 기본 모델.
- 화면 위 안내: Pi 없음 / 쓸 수 있는 모델 없음(로그인 필요) / 설정한 모델을 Pi에서 쓸 수 없음(Pi 기본 모델로 바꾸기) / Git Bash 없음.
- **Pi Desktop 설치**: GitHub의 Latest 릴리스(= Pi Desktop, Mate 릴리스는 Latest가 아님)에서 이 OS용 파일을 고르고(Mate 파일 제외),
  사용자 확인 뒤 다운로드 폴더에 내려받아 설치 프로그램을 연다. 이미 설치되어 있으면 "Pi Desktop 열기".
- 모델 칸은 쓸 수 있는 모델 목록에서 고른다 (직접 입력도 가능).

## 10. 활동 관찰 (M4)

사용자가 켜야만 동작한다 (기본 꺼짐). 같은 호스트의 Pi Desktop·터미널 `pi` 세션(`~/.pi/agent/sessions`)과 Agent 세션(`~/.pi-desktop-agent/sessions`)을 **읽기만** 한다 (DESIGN-APPS.md §3.3). 세 제품(Muse·Dots·Duet)이 "예약 + 연결된 데이터 관찰 + 기억"이라면, Mate는 코딩 작업의 흐름을 보고 **작업이 끝났을 때** 돕는다.

| | 내용 |
|---|---|
| 보는 것 | 사용자의 Pi 세션 기록(`~/.pi/agent/sessions`, Pi Desktop·터미널 Pi), 최근 작업한 저장소의 git 상태 |
| 보지 않는 것 | 화면, 키 입력, 다른 프로그램. 파일 내용·모델 답변은 기록하지 않는다 |
| 기록 | 세션 요약(요청 앞부분, 고친 파일, 명령 수·테스트 여부, 실패한 명령 앞부분, 모델 오류)만. 비밀값처럼 보이는 것은 가린다. Mate 홈 `activity.jsonl` (최근 1500줄) |
| 작업 끝 | 세션이 조용해지면(기본 5분). 관찰을 켜기 전에 조용해진 세션은 읽지 않는다 (켜자마자 알림이 쏟아지지 않게) |

작업이 끝나면:

1. **"작업을 마치면" 계기**(`session`): 그 폴더(또는 상위 폴더) 임무에 변화로 알린다 (쉬는 시간 기본 15분).
2. **규칙 알림** (모델 없이 바로): 오류로 끝난 세션(연결 오류면 VPN·프록시 확인 안내), push 안 한 커밋 하루, 커밋 안 한 변경 이틀.
3. **관찰자** (사용자가 쉬는 때, 모델): 고치고 테스트 안 돌림, 같은 실패가 하루 세 번. 저장소를 읽기만 하며 살펴보고 필요할 때만 제안 하나.
   고칠 일이면 맡길 일(followUp)을 붙이고, 사용자가 **"Mate에게 맡기기"**를 누르면 그 폴더에서 고치기(별도 작업 공간)로 실행해 다시 적용을 묻는다.

소음 관리: 하루 관찰 제안 상한(기본 5), 같은 일은 한 번만, 제외 폴더, 주제별로 버림만 세 번 넘고 받아들인 적 없으면 그 주제는 쉰다 (활동 탭 "배운 것").

## 11. 자동 업데이트

Mate 릴리스는 같은 저장소에 Latest가 아닌 릴리스로 올라가므로, electron-updater의 GitHub 방식(Latest만 봄)을 쓰지 않는다.

1. 시작 20초 뒤·6시간마다(설정의 "업데이트 확인"으로도) GitHub 릴리스 목록에서 가장 높은 `mate-vX.Y.Z`를 찾는다 (초안·사전 릴리스, Pi Desktop `v*`·Agent 제외).
2. 지금보다 높으면 그 릴리스 내려받기 주소를 generic 방식으로 넘겨 `latest.yml`(Windows)·`latest-linux.yml`(AppImage)을 읽는다.
3. Pi Desktop과 같은 확인 흐름: 새 버전 배지 → 업데이트할지 묻기 → 내려받기 → 다시 시작해 설치할지 묻기. 고르기 전에는 내려받지 않는다.
4. 설치 직전(지금 또는 앱을 끌 때) 실행기를 멈춘다. 다시 시작하면 바뀐 번들의 실행기가 뜬다.
5. macOS(서명 없음)·deb는 찾은 버전을 알리고 릴리스 페이지를 연다. `latest.yml`이 없는 릴리스(v0.2.0 이전)도 알리기로 대신한다.

업데이트 캐시는 `pi-desktop-mate-updater`로 Pi Desktop과 나뉜다. 개발 실행과 로컬 빌드(0.0.1)는 확인하지 않고, 시험할 때는 `PI_DESKTOP_MATE_UPDATE_URL`로 주소를 준다.
v0.2.0 이하는 업데이터가 없으므로 v0.3.0은 한 번 직접 설치해야 하고, 그다음부터 자동이다.

## 12. 휴대폰 연결 (텔레그램)

휴대폰으로 알림을 받고, 버튼으로 처리하고, 채팅으로 지시한다. 실행기 안에서 임무 실행과 따로 돌아 버튼에 바로 답한다.

| | 내용 |
|---|---|
| 연결 | PC → 텔레그램 바깥으로만(롱폴링). 공개 주소·포트를 열지 않는다. 회사 VPN·방화벽이 `api.telegram.org`를 막으면 쓸 수 없다 |
| 봇 | 사용자가 @BotFather로 만든 자기 봇. 토큰은 `getMe`로 확인하고 OS 키체인(safeStorage)으로 암호화해 설정에 둔다 |
| 토큰 전달 | 앱이 실행기를 띄울 때만 풀어 환경 변수로 넘긴다. 실행기는 Pi 실행 환경에서 이 변수를 뺀다(모델이 bash로 볼 수 없다) |
| 짝짓기 | 앱이 만든 10분짜리 일회용 코드를 봇에게 `/start 코드`로 보낸다(t.me 링크로도). 그 개인 채팅 하나만 받는다. 단체방·다른 채팅은 무시 |
| 연결 해제 | 앱이 연결 번호(pairEpoch)를 올리면 실행기가 연결을 버린다. 연결 상태는 실행기가 `remote.json`에 쓴다 |

휴대폰에서 할 수 있는 일은 앱과 같은 범위다.

- **알림**: 연결 뒤 생긴 인박스 항목. 기본은 할 일·확인 필요·고친 변경, 설정으로 전부. 조용한 시간에 생긴 것은 끝나면 보낸다.
- **버튼**: 확인함·버리기 / 고친 변경은 **적용(한 번 더 물음)**·버리기·diff 보기 / 맡길 일이 있으면 Mate에게 맡기기.
- **지시**: `/ask [폴더] 지시`(읽기만), `/fix [폴더] 지시`(고치기), `/run 임무`, `/inbox`, `/duties`, `/folders`, `/status`.
  폴더는 임무 폴더와 활동 관찰이 본 최근 작업 폴더에서 고른다. 휴대폰에서 시작한 실행은 끝나면 결과를 보낸다.
  빗금 없이 보낸 말은 Mate 대화로 넘긴다 (§13).
- **고치기**(/fix, 맡기기)는 설정에서 따로 허용해야 한다. 허용해도 별도 작업 공간에서 고치고, 적용은 다시 묻는다. bash는 여전히 읽기만, push·배포·삭제는 할 수 없다.
- 보내는 글은 비밀값처럼 보이는 것을 가리고 줄인다. diff·근거 내용을 보내지 않게 할 수 있다.

시험은 가짜 텔레그램 서버(`PI_DESKTOP_MATE_TELEGRAM_API`)로 한다. 단위 테스트(짝짓기·알림·버튼·지시·결과·연결 해제)와 dev:mock 앱에서 확인했다. 토큰 저장이 평문이 아닌지, 휴대폰 지시로 모델이 토큰 환경 변수를 읽으면 비어 있는지도 봤다.

## 13. Mate 대화

Mate와 늘 이어지는 대화 하나를 둔다. 사용자는 묻거나 시키고, Mate는 관찰·임무 중에 사용자의 판단이 필요하면 묻는다. 앱의 **대화** 탭과 휴대폰이 같은 대화를 쓴다.

| | 내용 |
|---|---|
| 기록 | `chat.jsonl` (추가만). 줄: 누가(user·mate), 종류(답·질문·알림·결과·구분선), 출처(앱·휴대폰), 질문이면 선택지·폴더·임무, 답이면 어느 질문의 답인지 |
| 담당 | 실행기 안의 대화 담당(ChatAgent). 임무 실행과 따로 돌아 임무가 도는 중에도 답한다. 받은 말은 한 번에 하나씩 처리 |
| 받기 | 앱은 사용자 줄을 먼저 남기고 `chat/requests`에 요청 파일을 넣는다. 휴대폰은 같은 프로세스에서 바로 넘긴다 |
| `/` 명령 | 모델 없이 바로 답한다: `/status` `/inbox` `/duties` `/folders` `/run` `/ask` `/fix` `/new` `/help`. 앱과 휴대폰이 같은 처리를 쓴다. `/history`는 휴대폰 전용 (앱은 대화 탭에 다 보임) |
| 그 밖의 말 | Pi로 답한다. 같은 세션(`mate-chat-<번호>`, `chat/sessions`)을 이어 써서 앞의 말을 기억한다. `/new`·**새 대화**는 번호를 올린다 |
| 맥락 | 차례마다 시스템 안내에 지금 상태를 붙인다: 임무·아는 폴더·새 제안(id·요약)·답하지 않은 질문·최근 실행·최근 관찰한 작업. 모델이 묻지 않고도 답하게 한다 |
| 권한 | 대화 단계(chat): 읽기 도구 + `mate_do`. bash는 다른 단계처럼 읽기만 통과한다. 파일을 바꾸지 않는다 |

**시키기(mate_do)**: 대화 중 Mate는 할 일을 `mate_do`로 실행기에 맡긴다. 그 차례가 끝난 뒤 실행기가 처리하고, 처리 결과를 알림 줄로 남긴다.

- 할 일: 임무 실행, 폴더 살펴보기(ask), 고치기(fix: 별도 작업 공간, 적용은 다시 승인), 제안 확인·버리기·맡기기, 임무 만들기(실행 시점: manual·daily HH:MM·weekdays HH:MM·every N minutes/hours[ HH:MM-HH:MM][ weekdays]·on-commit·after-session), 자동 실행 일시 정지·다시 시작, 웹 검색 켜기(enable_web: 사용자가 버튼으로 허용).
- 고친 변경의 적용·버리기는 대화로 하지 않는다. 앱·휴대폰의 버튼으로만 한다 (승인은 사람이 직접).
- 휴대폰에서 온 대화의 고치기·맡기기는 휴대폰 설정의 "고치기 허용"을 따른다.
- 대화에서 시작한 실행은 끝나면 결과 줄을 남긴다 (휴대폰에서 시작했으면 휴대폰으로도).

**대화로 하고 싶은 일 이루기**: 사용자는 앱 사용법이나 용어(MCP·프로필·임무 설정)를 모를 수 있다. Mate가 길을 먼저 찾아 제안하고, 사용자는 말과 버튼으로만 정한다. "못 해요"로 끝내지 않는다.

- 인터넷이 필요한 일(날씨·뉴스·검색·웹 페이지): 웹 검색이 꺼져 있으면 Mate가 `mate_do`의 `enable_web`을 부른다. 실행기는 "웹 검색을 켤까요?" 질문을 올린다(무엇이 밖으로 나가는지 한 줄로: 검색어·페이지 주소가 mcp.exa.ai로). 허용하면 키가 필요 없는 Exa 서버를 mcp.json에 넣고(꺼져 있으면 켠다) 대화에 고르고(`chatMcpServers`), 도구를 허용하고(`chatGrants`), **방금 요청에 다시 답한다**. 시스템 안내의 상태 줄에 "웹 검색 켜짐/꺼짐"을 적는다.
- 대화에서 막힌 MCP 도구를 허용해도 방금 요청에 다시 답한다 (질문의 `permission.retry`).
- 되풀이하고 싶은 일은 양식을 채우게 하지 않고, 대화에서 알아낸 것으로 정해 "매일 아침 7시에 서울 날씨를 알려 드릴까요?"처럼 한 번에 확인받은 뒤 `create_duty`로 만든다.
  - 폴더와 상관없는 일은 folder를 비운다. Mate 홈의 `workspace/`에서 돈다.
  - 시스템 안내에 만들 수 있는 실행 시점을 모두 적고, 그 밖의 것(하루 여러 시각 등)은 제안하지 않게 한다. 하루 자동 실행 상한을 넘을 만큼 자주 돌리려 하면 간격을 늘리거나 시간대를 좁히자고 제안한다.
  - `web: true`면 임무에 웹 검색 서버를 넣는다. 대화에서 이미 허용한 웹 검색 도구는 임무에도 허용해 두고(같은 것을 두 번 묻지 않게), 아니면 처음 실행할 때 묻는다.

**묻기(mate_ask)**: 제안·고치기 단계의 임무와 관찰자 실행은 사용자의 판단이 필요하면 `mate_ask`로 묻는다 (예: "테스트를 추가할까요?", 선택지 2~4개).

- 답을 기다리지 않는다. 물은 뒤 할 수 있는 만큼 하고 끝낸다. 답하지 않은 같은 질문은 하루 안에 다시 묻지 않는다.
- 질문은 대화 탭(배지)과 휴대폰(선택지 버튼, 조용한 시간은 지킴)에 뜬다. 버튼을 누르거나, 휴대폰에서 질문에 답장하거나, 앱에서 **직접 답하기**로 답한다.
- 답은 질문(글·폴더·임무)을 붙여 대화로 넘긴다. Mate가 그 답에 따라 일을 맡긴다 (예: "예" → 그 폴더에서 테스트 추가를 고치기로).

화면: 대화 탭은 대화 줄과 아직 처리하지 않은 제안 카드를 시간 순서로 함께 보여 준다. 입력창에 `/`를 치면 명령 목록이 나온다. 답을 쓰는 중이면 "답을 쓰는 중…"을 보인다.
휴대폰: 빗금 없는 말은 대화로 보내고 "입력 중…"을 보인다. 기본으로는 휴대폰에서 시작한 대화의 답과, 어디서 왔든 Mate의 질문만 휴대폰으로 보낸다. 앱과 휴대폰은 같은 Pi 세션을 쓰므로 앱에서 나눈 말도 휴대폰에서 이어 말할 수 있다.
- `/history [줄 수]`: 지금 대화(마지막 새 대화 뒤)의 최근 줄을 🖥 앱·📱 휴대폰 표시와 함께 보여 준다 (기본 10줄, 최대 30줄).
- 휴대폰 탭의 **앱 대화도 휴대폰으로 보내기**: 켜면 그 뒤에 앱에서 나눈 말과 답을 🖥 표시로 보낸다. 켜기 전 대화는 보내지 않는다(`mirrorAppSince`). 조용한 시간의 앱 대화는 보내지 않고 건너뛴다 (끝난 뒤 몰아 보내지 않음, /history로 본다).

비용: 대화 차례마다 실행당 비용 상한을 쓰고, 오늘 대화 비용을 `chat/state.json`에 따로 센다 (하루 자동 실행 상한에는 넣지 않는다).

시험: 가짜 Pi로 대화 담당(요청 파일·명령·할 일·질문·새 대화)과 휴대폰 대화(답·질문 버튼·결과)를 단위 테스트했다. dev:mock 앱에서 실제 Pi로 일반 대화, `mate_do` 임무 실행과 결과 줄, 임무의 `mate_ask` 질문과 선택지 답, 세션 이어 쓰기와 새 대화를 확인했다.
