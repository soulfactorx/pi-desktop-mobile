# Pi Desktop Mate

묻기 전에 먼저 살펴보고 알려 주는 **능동형 코딩 동료**. 정한 때에 Pi가 작업 폴더를 읽기만 하며 살펴보고, 결과와 제안을 인박스에 남긴다.
설계는 [docs/DESIGN-MATE.md](../../docs/DESIGN-MATE.md).

Pi Desktop(`apps/desktop`)·Pi Desktop Agent(`apps/agent`)와는 별도 앱이다. 데이터 홈도 따로 쓴다(`~/.pi-desktop-mate`).
Pi 설정·로그인(`~/.pi/agent`)은 같이 쓰므로 API 키를 다시 넣을 필요가 없다.

## 구성

| 패키지 | 하는 일 |
|---|---|
| `apps/mate` | Electron 앱: 인박스·임무·실행 기록·설정 |
| `packages/mate-runner` | 상주 실행기: 시간표를 지키고 실행마다 `pi --mode json`을 띄운다. 앱을 닫아도 돈다 |
| `packages/mate-kit` | Pi 확장: 권한 단계 강제(`mate-guard`), 제안 도구(`mate_propose`) |

## 준비

Mate는 이 PC의 Pi로 일한다 (Pi Desktop과 같은 Pi·로그인·모델). Pi Desktop 앱이 없어도 되지만, Pi가 설치되어 있고 프로바이더 하나에 로그인되어 있어야 한다.
준비가 안 되어 있으면 화면 위에 안내가 나오고, **Pi Desktop 설치**(최신 설치 파일을 내려받아 설치 프로그램을 엶) 또는 **Pi Desktop 열기**로 Pi 설치·로그인을 하면 된다.

## 쓰는 법

1. **임무** 탭에서 새 임무를 만든다 (템플릿: 아침 브리핑·CI 확인·의존성 점검).
   - 하는 일: **보고**(실행마다 결과 한 건), **제안**(알릴 것이 있을 때만), **고치기**(별도 작업 공간에서 고치고 승인을 기다림, git 저장소만).
   - 언제: 직접 실행만 / 일정 간격(최소 15분) / 정한 시각(요일 선택) / 저장소 변화(새 커밋) / 파일 변화(저장이 잠잠해지면) / 명령 결과 변화(예: `gh run list`).
   - 변화 계기는 처음 본 상태를 기준으로 삼고, 한 번 돈 뒤 쉬는 시간(기본 15분) 안의 변화는 모았다가 한 번 돈다.
2. **지금 실행**으로 바로 돌려 보거나, 시간표를 기다린다.
   - "작업을 마치면" 계기: 이 폴더에서 Pi Desktop·터미널 Pi·Agent로 한 작업이 끝나면 돈다 (활동 관찰을 켜야 함).
3. 앱을 켜면 **인박스**에 쌓인 결과·제안을 보고 확인함·버리기를 누른다.
   고치기 결과는 diff를 보고 **적용**(내 작업 폴더에 커밋하지 않은 변경으로 들어옴, 커밋은 직접) 또는 **버리기**를 누른다.

보고·제안은 파일을 바꾸지 않는다(쓰기 도구를 Pi에 선언하지 않음). 고치기는 사용자 저장소 HEAD에서 만든 별도 git worktree(`~/.pi-desktop-mate/worktrees`, 브랜치 없음) 안만 고칠 수 있고, 적용 전까지 내 작업 폴더는 그대로다.
bash는 어느 단계든 읽기 명령(git·gh 조회, ls·cat·grep 등)만 통과한다.
기본 모델은 `anthropic/claude-haiku-5-5`이고 설정에서 목록으로 바꾼다. **Pi 기본 모델 따르기**를 고르면 Pi Desktop에서 바꾼 기본 모델을 따른다.

알아 둘 것:

- 실행기는 앱을 열 때 뜨고, 앱을 닫아도 남는다. 설정의 **로그인할 때 실행기 시작**(설치본만)을 켜면 PC를 다시 켠 뒤 앱을 열지 않아도 돈다 (창은 뜨지 않음).
- 꺼져 있던 동안 놓친 시간표는 한 번만 따라잡는다. 하루 자동 실행 상한(기본 20회), 실행당 시간 제한(기본 300초), 실행당 비용 상한(기본 $0.5)이 있다.
- 실행 세션은 `~/.pi-desktop-mate/sessions`에 남아 Pi Desktop·TUI 세션 목록에 섞이지 않는다. Pi Desktop의 스킬·프롬프트·확장·사용자 지침(`~/.pi/agent/AGENTS.md`)도 임무에 끼어들지 않는다. 스킬·프롬프트는 `~/.pi-desktop-mate/skills`·`prompts`의 것만 쓰고, 작업 폴더의 `AGENTS.md`·`CLAUDE.md`는 읽는다. 실행 기록의 **세션 보기**로 무엇을 읽고 어떤 명령이 막혔는지 볼 수 있다.

- 지운 임무·실행 기록·대화는 **휴지통** 탭으로 간다 (`~/.pi-desktop-mate/trash`). 되살리면 원래 자리로 돌아가고, 비우면 정말 지운다. 실행 기록이 200개를 넘으면 오래된 것을 한 묶음으로 휴지통에 옮긴다. 대화 탭의 **기록 지우기**로 대화 기록을 치울 수 있고, 되살리면 그사이 나눈 대화와 시각 순으로 합친다.

## 대화

**대화** 탭에서 Mate에게 그냥 말로 묻거나 시킨다. 휴대폰(텔레그램)에서 나눈 대화도 같은 대화다.

- 묻기: "오늘 뭐 했어?", "새 제안 중에 급한 거 있어?", "CI watch 임무는 언제 돌아?"
- 시키기: "pi-desktop CI 왜 깨졌는지 살펴봐 줘", "매일 아침 9시에 의존성 점검하는 임무 만들어 줘", "그 린트 경고 제안은 버려 줘", "오늘은 자동 실행 멈춰 줘".
  시킨 일은 실행기가 돌리고, 끝나면 결과가 대화에 온다. 고치기는 별도 작업 공간에서 하고 적용은 다시 묻는다.
- 명령: `/status` `/inbox` `/duties` `/folders` `/run 임무` `/ask [폴더] 지시` `/fix [폴더] 지시` `/new` — 모델 없이 바로 답한다.
- Mate의 질문: 관찰·임무 중 판단이 필요하면 Mate가 묻는다 (탭 배지). 선택지 버튼이나 **직접 답하기**로 답하면 Mate가 이어서 처리한다.
- **새 대화**(`/new`)는 앞의 대화를 잊고 새로 시작한다.

## 활동 관찰

**활동** 탭에서 켜면, Pi Desktop·터미널 Pi·Pi Desktop Agent로 한 작업이 끝날 때마다 Mate가 도울 거리를 찾아 인박스에 남긴다 (기본 꺼짐).

- 보는 것: Pi 세션 기록(`~/.pi/agent/sessions`, Agent의 `~/.pi-desktop-agent/sessions`. 요청·고친 파일·실패한 명령·오류의 요약만 남기고 파일은 읽기만 한다)과 최근 작업한 저장소의 git 상태. 화면·키 입력은 보지 않는다.
- 알리는 것: 연결 오류로 끝난 세션(VPN 확인 안내), 오래 push 안 한 커밋, 오래 커밋 안 한 변경, 고치고 테스트를 안 돌림, 같은 실패 반복.
- 제안에 **Mate에게 맡기기**가 있으면 눌러서 바로 고치게 할 수 있다 (별도 작업 공간에서 고치고, 적용은 다시 묻는다).
- 계속 버리는 주제는 덜 알린다. 하루 제안 상한과 제외 폴더를 정할 수 있다.

## 휴대폰 연결 (텔레그램)

**휴대폰** 탭에서 연결하면 휴대폰 텔레그램으로 알림을 받고, 버튼으로 확인·적용·버리기·맡기기를 하고, 채팅으로 지시할 수 있다.

1. 텔레그램에서 @BotFather에게 `/newbot`을 보내 내 봇을 만들고, 받은 토큰을 붙여 넣는다 (OS 키체인으로 암호화해 이 PC에만 저장).
2. **연결 코드 만들기**를 누르고, 휴대폰에서 봇에게 `/start 코드`를 보낸다 (10분 안에).
3. 알림이 오면 버튼으로 처리한다. 고친 변경의 **적용**은 한 번 더 묻는다.
4. 그냥 말로 묻거나 시키면 Mate 대화로 답한다 (앱 대화 탭과 같은 대화). Mate의 질문은 선택지 버튼으로 오고, 질문에 답장해도 된다.
5. 명령: `/ask pi-desktop CI 실패 원인 찾아줘`, `/fix …`(설정에서 허용해야), `/run 아침 브리핑`, `/inbox`, `/status`, `/new`, `/help`.

PC의 실행기가 텔레그램에 바깥으로만 연결하므로 포트를 열 필요는 없지만, 회사 VPN이 텔레그램을 막으면 쓸 수 없다. 보내는 글은 텔레그램 서버를 거치므로 비밀값을 가리고 줄여서 보내고, diff를 보내지 않게 할 수도 있다.

## 설치와 릴리스

- 설치 파일: GitHub Releases의 `mate-v*` 릴리스 (Windows `Pi-Desktop-Mate-Setup-*.exe`, macOS dmg, Linux AppImage/deb). 코드 서명이 없어 처음 실행할 때 경고가 나올 수 있다 ([루트 README의 "코드 서명"](../../README.md#코드-서명)).
- 릴리스 만들기: `mate-v`로 시작하는 태그(예: `mate-v0.5.2`)를 올리면 `.github/workflows/mate-release.yml`이 세 OS에서 만들어 올린다. Actions에서 손으로 돌리면 만들기만 한다.
- Pi Desktop과 별도 앱이다. Mate 릴리스는 GitHub에서 Latest로 표시하지 않아 Pi Desktop 자동 업데이트에 섞이지 않는다.
- **자동 업데이트**(v0.3.0부터): 새 버전이 나오면 상단에 "새 버전" 배지가 뜨고, 누르면 내려받아 다시 시작할 때 설치한다(Windows·AppImage. macOS는 릴리스 페이지 안내). 설정의 "업데이트 확인"으로 바로 확인할 수 있다. v0.2.0 이하는 v0.3.0을 한 번 직접 설치해야 한다.
- 로컬에서 만들기: `npm run dist -w @pi-desktop/mate` (지금 OS용, 결과는 `apps/mate/release/`)

## 개발

```bash
npm run dev:mock -w @pi-desktop/mate
```

API 키 없이 mock LLM(포트 18913)으로 띄운다. Mate 홈은 `.dev/mate-home`, Pi 설정은 `.dev/mate-pi-agent`라 실제 데이터와 Pi Desktop·Agent 개발 실행을 건드리지 않는다.
임무 지시에 다음을 넣으면 mock이 그대로 행동한다.

- `안녕` → `echo: 안녕` (보고 결과 확인)
- `tool:mate_propose {"title":"…","summary":"…","severity":"warn"}` → 제안
- `bash:rm -f hello.txt` → 막히는지 확인

```bash
npm test -w @pi-desktop/mate-runner
```

이 명령은 실행기를 빌드한 뒤, 실제 Pi와 mock LLM으로 계약 테스트를 돌린다. 확인하는 것은 제안·중복 제거, 쓰기·`rm` 차단, 상주 실행기의 지금 실행이다.
