# Pi Desktop

[Pi coding agent](https://pi.dev)를 **포크하지 않고**, 설치된 `pi` 그대로 GUI로 쓰는 데스크톱 앱입니다.
Pi를 업데이트하면 앱도 그대로 따라갑니다.

이 모노레포의 첫 앱이며, Pi 설치·로그인·프로바이더·모델 관리는 이 앱이 맡습니다. 다른 두 앱([Pi Desktop Agent](../agent/README.md), [Pi Desktop Mate](../mate/README.md))도 여기서 설정한 Pi를 함께 씁니다.

- 설계: [docs/DESIGN.md](../../docs/DESIGN.md)
- 현재 단계: 로드맵 M1~M5(채팅, Pi 관리·프로바이더, WSL·SSH, 리소스·Marketplace·호스트 간 복사, 개발자 도구·배포)를 마치고 `v*` 릴리스로 배포 중

## 구조

```
apps/desktop/          Electron 앱 (main · preload · React 렌더러)
packages/host-protocol 앱 ↔ Host Agent 메시지 형식 (JSONL, JSON-RPC 2.0)
packages/host-agent    대상 호스트에서 도는 상주 데몬(agentd)과 연결기(connect)
```

앱은 `host-agent connect`를 띄워 데몬에 붙고, 데몬이 `pi --mode rpc` 프로세스와 이벤트 저널을 소유합니다.
그래서 앱을 닫아도 Pi는 계속 작업하고, 다시 열면 놓친 이벤트를 재생해 이어서 보여줍니다 (설계 §3.4).

## 설치와 업데이트

[Releases](https://github.com/skax-soulfactor/pi-desktop/releases)에서 OS에 맞는 파일을 받습니다.

| OS | 파일 | 자동 업데이트 |
|---|---|---|
| Windows | `Pi-Desktop-Setup-<버전>.exe` | 업데이트할지 물은 뒤 내려받고, 다시 시작해 설치할지 한 번 더 묻습니다 |
| macOS | `Pi-Desktop-<버전>-arm64.dmg` / `-x64.dmg` | 새 버전을 알리고 릴리스 페이지를 엽니다 (아래 "코드 서명") |
| Linux | `Pi-Desktop-<버전>-x86_64.AppImage` / `.deb` | AppImage는 Windows와 같고, deb는 알리기만 합니다 |

앱은 시작 15초 뒤와 6시간마다 새 버전을 확인하고, 있으면 탭 바에 "새 버전 <버전> 업데이트…" 배지만 보입니다. 묻기 전에는 아무것도 내려받거나 설치하지 않습니다.

- 배지나 도움말 → "업데이트 확인…"(명령 팔레트의 "업데이트 확인")을 누르면 업데이트할지 묻습니다. 업데이트를 고르면 내려받은 뒤, 지금 다시 시작해 설치할지 묻습니다. 나중에를 고르면 앱을 끌 때 설치합니다.
- 직접 확인했는데 새 버전이 없으면 "최신 버전입니다"라고 알리고, 확인하지 못하면 이유를 보입니다.
 `npm run dist`로 직접 만든 빌드(버전 0.0.1)는 확인하지 않습니다.

**코드 서명**: 세 앱 모두 서명하지 않습니다. 처음 실행할 때의 경고와 넘어가는 법은 [루트 README의 "코드 서명"](../../README.md#코드-서명)을 보세요. macOS는 서명이 없으면 자동 설치가 거부되므로, 앱은 새 버전을 알리고 릴리스 페이지를 엽니다.

**릴리스를 올리는 곳**: 지금은 이 저장소의 GitHub Releases입니다(공개 저장소라 토큰 없이 확인합니다). `apps/desktop/electron-builder.yml`의 `publish`만 바꾸면 다른 곳을 쓸 수 있습니다.
- 다른 GitHub 저장소: `owner`·`repo`를 바꿉니다. 예를 들어 소스는 비공개로 두고 배포용 공개 저장소만 따로 둘 수 있습니다.
- 내 웹 서버·S3·Cloudflare R2 등: `provider: generic`과 `url`을 씁니다. 그 주소에 설치 파일과 `latest*.yml`을 올리면 됩니다. `provider: s3`로 S3에 직접 올릴 수도 있습니다.
- 비공개 GitHub 저장소: 앱이 확인할 때 토큰이 필요해 일반 배포에는 맞지 않습니다.

**릴리스 만들기**(관리자): 버전 태그를 올리면 GitHub Actions(`.github/workflows/release.yml`)가 세 OS에서 설치 파일을 만들어 Releases에 올립니다. 앱 버전은 태그를 따릅니다.

```bash
git tag -a v0.1.0 -m "Pi Desktop v0.1.0"
```

```bash
git push origin v0.1.0
```

Actions 탭에서 "Release"를 손으로 돌리면 만들기만 하고 올리지 않습니다(릴리스 전 미리 확인). 로컬에서 지금 OS용 설치 파일만 만들 때는 `npm run dist -w @pi-desktop/desktop`을 씁니다(결과는 `apps/desktop/release/`).

## Android 휴대폰에서 쓰기 (웹 버전 pi-web)

Electron 앱은 Android에서 돌지 않습니다. 대신 휴대폰의 [Termux](https://termux.dev)에서 Pi와 웹 서버 **pi-web**을 돌리고, 휴대폰 브라우저(Chrome·삼성 인터넷)로 같은 화면을 엽니다. VS Code의 code-server와 같은 방식입니다 (설계 §5.10).

1. Termux를 [F-Droid](https://f-droid.org/packages/com.termux/)나 [GitHub](https://github.com/termux/termux-app/releases)에서 설치합니다 (Play 스토어 판은 오래되었습니다).
2. Termux에서 한 줄로 설치하고 켭니다. Node.js·Pi·pi-web을 설치하고 브라우저를 엽니다.

   ```bash
   curl -fsSL https://github.com/soulfactorx/pi-desktop-mobile/releases/latest/download/install-termux.sh | bash
   ```

   - 내장 터미널(셸, OAuth `/login`)도 쓰려면 끝에 `-s -- --terminal`을 붙입니다. node-pty를 휴대폰에서 빌드하느라 빌드 도구(수백 MB)를 받습니다.
   - 인터넷 없이: 릴리스의 `pi-web.tar.gz`와 `install-termux.sh`를 받아 `bash install-termux.sh --file pi-web.tar.gz`.
3. 브라우저가 `http://127.0.0.1:8787/#token=…`로 열립니다. 주소 끝의 토큰은 이 브라우저에 기억됩니다. Chrome 메뉴의 "홈 화면에 추가"로 앱처럼 쓸 수 있습니다.
4. "프로바이더"에서 API 키를 넣고, "폴더 선택"으로 휴대폰 안의 작업 폴더(예: `~/projects/app`)를 고르면 데스크톱과 똑같이 씁니다.

| 명령 | 하는 일 |
|---|---|
| `pi-web` | 서버를 켜고 브라우저를 엽니다 (`pi-web start`) |
| `pi-web url` | 토큰이 든 주소를 보여 줍니다 (다른 브라우저에서 열 때) |
| `pi-web stop` / `restart` / `status` / `log` | 끄기·다시 켜기·상태·서버 기록 |
| `pi-web update` | 최신 릴리스로 업데이트 (토큰·설정은 그대로) |
| `pi-web uninstall` | 지우기 (데이터 `~/.pi-web/data`는 남깁니다) |
| `pi-web agent` | **Pi Desktop Agent** 웹 버전을 켜고 엽니다 (포트 8788). 승인·지식베이스·스킬·예약 작업. 기능 화면은 오른쪽 위 ⋮ 메뉴에서 엽니다 |
| `pi-web mate` | **Pi Desktop Mate** 웹 버전을 켜고 엽니다 (포트 8789). 임무 시간표·인박스·텔레그램. 서버를 꺼도 실행기는 임무를 계속 돌립니다 |
| `pi-web all` | 세 앱을 모두 켭니다. `stop`·`status`·`url`도 앱 이름 뒤에 씁니다 (예: `pi-web mate stop`, `pi-web all status`) |

- 설치 중 `CANNOT LINK EXECUTABLE "curl": cannot locate symbol …`이 나오면 Termux 패키지가 일부만 업데이트된 것입니다. `pkg upgrade -y` 뒤에 설치 명령을 다시 실행하세요 (v0.1.1부터 설치 스크립트가 먼저 업그레이드합니다).
- **파일 관리자**: ⋮ 메뉴 → **파일 관리자**에서 Termux 홈 폴더를 훑고, 새 폴더·파일, 이름 바꾸기, 복사·이동, 지우기, 글 파일 보기·고치기를 합니다. **올리기**로 휴대폰의 사진·문서를 넣고, 파일의 ⋯ → **휴대폰으로 내려받기**로 꺼냅니다. **📱 저장소**는 휴대폰 공용 저장소(`~/storage`, 한 번 `termux-setup-storage`를 실행해야 생깁니다)입니다. **이 폴더에서 새 세션**으로 바로 Pi 세션을 엽니다.
- **휴대폰 알림**: Pi Web·Agent·Mate 화면을 처음 열면 아래에 "휴대폰 알림을 켤까요?"가 뜹니다. **알림 켜기**를 누르고 허용하면, 화면을 보고 있지 않을 때(브라우저를 닫아도) 휴대폰 알림으로 받습니다. Pi Web은 작업 끝남·답을 기다림, Agent는 대화 답·승인 요청·작업 끝남, Mate는 답·질문(승인 요청)·임무 결과·새 제안. 구글 푸시 서버를 거치므로 휴대폰이 인터넷에 붙어 있어야 합니다. 앱마다 따로 켭니다.
- Agent·Mate 웹 버전은 각 앱 화면을 그대로 씁니다 (설계 §5.11). 폴더·파일 고르기는 화면 안의 창으로 휴대폰(Termux) 폴더를 훑고, 파일 첨부는 "휴대폰에서 올리기"로 사진·문서를 올립니다. Pi 로그인·모델은 Pi Desktop(`pi-web`)에서 한 번 하면 함께 씁니다.
- 서버를 끄거나 브라우저를 닫아도 Pi 작업은 데몬에서 계속 돕니다. 다시 열면 이어서 보여 줍니다. 브라우저가 백그라운드에서 연결을 끊어도 화면으로 돌아오면 다시 붙습니다.
- 갤럭시가 Termux를 멈추지 않게: 설정 → 애플리케이션 → Termux → 배터리 → **제한 없음**, 개발자 옵션 → **하위 프로세스 제한 사용 중지**(Android 14 이상). `pi-web`은 켤 때 Termux wake lock을 겁니다.
- 서버는 휴대폰 안(127.0.0.1)에서만 열립니다. 다른 기기(태블릿·PC)에서 휴대폰의 Pi를 쓰려면 `PI_WEB_HOST=0.0.0.0 pi-web restart`로 열 수 있지만, 같은 Wi-Fi의 누구나 접속을 시도할 수 있으니 Tailscale 같은 VPN 안에서만 쓰기를 권합니다.
- 일반 Linux 서버에서도 같은 스크립트로 설치할 수 있습니다 (Node.js 22.19 이상, 명령은 `~/.local/bin/pi-web`).
- 직접 만들기: `npm run dist:web -w @pi-desktop/desktop` → `apps/desktop/release/web/`. 개발 실행(mock LLM): `npm run dev:web -w @pi-desktop/desktop`. 릴리스 태그(`v*`)를 올리면 Actions가 두 파일을 Releases에 함께 올립니다.

## 개발 환경

Node.js·Git Bash 같은 공통 준비와 `npm install`은 [루트 README의 "개발"](../../README.md#개발)을 따릅니다.

앱 아이콘 원본은 `apps/desktop/build/icon.svg`입니다. 고친 뒤 `npx electron apps/desktop/scripts/render-icon.mjs`로 `build/icon.png`(1024px)를 다시 만들면, 설치 파일을 만들 때 각 OS 아이콘이 이것으로 만들어집니다.

npm 11은 설치 스크립트를 기본으로 막습니다. Electron 바이너리 다운로드는 루트 `package.json`의 `allowScripts`로 허용해 두었습니다.

## 실행

### API 키 없이 mock LLM으로 실행

```bash
npm run dev:mock -w @pi-desktop/desktop
```

- 저장소의 Pi devDependency(1.3.0)와 OpenAI 호환 mock LLM(포트 18911)을 씁니다.
- Pi 설정과 데몬 홈은 저장소의 `.dev/` 아래로 격리되어 실제 `~/.pi`, `~/.pi-desktop`과 섞이지 않습니다.
- 프롬프트 예: `안녕` → 그대로 echo, `read:package.json` → read 툴 호출 후 내용 응답, `bash:<명령>` → bash 툴 호출, `tool:<툴 이름> <JSON 인자>` → 그 툴 호출 (예: `tool:edit {"path":"a.txt","edits":[{"oldText":"a","newText":"b"}]}`). `fail:529` → 그 HTTP 상태의 오류 응답 (자동 재시도 확인용). 개발 실행에서는 grep·find·ls 툴도 켜져 있습니다.
- `-- --demo-ext`를 붙이면 Pi에 들어 있는 rpc-demo 확장을 함께 불러옵니다. 확장 UI(다이얼로그·알림·위젯·상태)를 확인할 때 씁니다.
  - `/rpc-input`, `/rpc-editor`, `/rpc-prefill` 명령, `bash:rm -rf ./x`(위험 명령 확인 다이얼로그)

### 설치된 Pi로 실행

```bash
npm run dev -w @pi-desktop/desktop
```

루트의 `npm run dev`도 같은 명령입니다. 상단의 호스트 선택에서 Pi가 설치된 곳을 고릅니다.

- **로컬 (Windows)**: `npm install -g @earendil-works/pi-coding-agent`로 설치하고 `pi`에서 `/login`을 해 두어야 합니다.
- **WSL: <배포판>**: WSL 안에 Pi가 설치되어 있고(공식 설치기 또는 npm) 로그인되어 있으면 됩니다.
  - 앱이 Host Agent를 WSL 홈의 `~/.pi-desktop/agent/`에 자동으로 올리고, WSL 안에 데몬을 띄웁니다.
  - 작업 폴더는 WSL 안의 경로(예: `/home/me/project`)로 입력하거나 "폴더 선택"으로 WSL 안의 폴더를 훑어 고릅니다. 글자를 쳐서 거르고, Enter로 들어가고, Backspace로 위로, Ctrl+Enter로 지금 폴더를 고릅니다.
  - WSL에 Node.js 22 이상이 필요합니다. Pi 공식 설치기가 깐 Node도 자동으로 찾습니다.

- **SSH: <이름>**: 호스트 선택 목록의 "SSH 호스트 관리…"에서 이름·접속 대상(`user@host` 또는 `~/.ssh/config`의 Host 이름)·포트를 등록합니다.
  - **키 인증만 됩니다.** 앱은 비밀번호를 묻거나 저장하지 않습니다. `ssh-keygen`으로 키를 만들어 서버의 `~/.ssh/authorized_keys`에 공개 키를 등록하세요 (암호 건 키는 ssh-agent에 올려 두어야 합니다).
  - 서버에 Node.js 22 이상이 필요합니다. 앱이 Host Agent를 서버 홈의 `~/.pi-desktop/agent/`에 올리고 서버에 데몬을 띄웁니다. 앱을 닫거나 연결이 끊겨도 서버의 Pi는 계속 돌고, 다시 열면 이어 붙습니다.
  - Pi가 없으면 Pi 관리 창의 설치 안내를 "터미널에서 실행"으로 서버에서 돌립니다 (내장 터미널이 `ssh -t`로 붙습니다).
  - Android 휴대폰도 됩니다: Termux에서 `pkg install openssh nodejs-lts` 후 `sshd`를 켜고 (포트 8022) 키를 등록하세요. Pi는 npm 전역으로 설치합니다.
  - 연결이 안 되면(서버가 꺼짐, 주소(IP)가 바뀜) 상단 배지에 "N초 뒤 다시 시도 (n/6)"가 나오며 점점 길게 기다렸다 다시 붙습니다. 연달아 6번(약 1분) 실패하면 멈추고, 이유와 "다시 연결"·"SSH 호스트 관리…"를 보입니다. 서버를 켜거나 주소를 고친 뒤 "다시 연결"을 누르세요. 그 호스트를 목록에서 다시 골라도 다시 붙습니다.

앱은 마지막으로 고른 호스트를 기억하고, 다시 열면 그 호스트의 최근 세션에 자동으로 다시 붙습니다.

## 테스트

이 앱과 이 앱이 쓰는 패키지만 돌릴 때는 다음처럼 합니다. 루트의 `npm test`는 모든 워크스페이스를 돌립니다.

```bash
npm test -w @pi-desktop/host-protocol -w @pi-desktop/host-agent -w @pi-desktop/desktop
```

- `host-protocol`: 프레이밍(U+2028, 멀티바이트 경계 등)과 JSON-RPC
- `host-agent`: 가짜 Pi로 데몬·재연결·저널 잘림 검증, **실제 Pi 1.3.0 + mock LLM 계약 테스트**
- `desktop`: 이벤트 → 채팅 상태 리듀서

## 여러 프로젝트를 탭으로

- 탭마다 호스트와 세션을 따로 고릅니다. 숨긴 탭의 작업도 계속 돌고, 끝나거나 입력이 필요해지면 탭에 "완료"·"입력 필요"를 표시하고 OS 알림을 띄웁니다.
- 탭 목록은 저장되어 앱을 다시 열면 돌아옵니다. 세션을 열지 않은 빈 탭은 되살리지 않습니다(첫 탭은 늘 남음). 탭을 닫아도 Pi 세션은 계속 돌고, 사이드바의 "실행 중"에서 다시 열 수 있습니다.
- 탭 바 오른쪽 "활동"을 누르면 모든 탭·호스트의 세션이 입력 필요 → 작업 중 → 대기 순으로 보입니다. 누르면 그 세션을 보는 탭으로 가거나 새 탭으로 엽니다. 버튼의 배지는 작업 중인 세션 수이고, 입력이 필요하면 주황색으로 바뀝니다.
- 단축키: `Ctrl+T` 새 탭, `Ctrl+W` 탭 닫기, `Ctrl+Tab`·`Ctrl+Shift+Tab` 탭 이동, `Ctrl+1~9` 탭 고르기.

## Pi 관리

- 상단 바의 "Pi 1.3.0" 버튼(또는 명령 팔레트의 "Pi 관리")으로 호스트별 Pi 상태를 봅니다.
  - Pi: 설치 방식·경로, 레지스트리 최신 버전과 비교
  - Node: 버전과 Pi가 요구하는 버전 충족 여부
  - Git Bash: Windows만
  - 데이터: 세션 수·크기, 인증된 프로바이더 이름, 설정 파일
- 새 버전이 있으면 버튼에 "↑ 새 버전"이 표시됩니다. 최신 버전은 `npm view`로 확인하고, npm이 없거나 실패하면 npm 레지스트리에 직접 묻습니다. 확인에 실패하면 2분 뒤, 성공하면 6시간마다 다시 확인합니다.
- 호스트에 Pi가 없으면 버튼이 "Pi 없음"으로 바뀌고, 사이드바 기록 자리에 "Pi 설치하기" 버튼이 나옵니다. 누르면 Pi 관리의 설치 화면이 열립니다. 설치·업데이트·제거 명령을 실행하면 끝날 때까지 몇 초마다 다시 확인해 버튼과 기록을 저절로 갱신합니다.
- Pi 관리 창에서 "Pi 업데이트", "패키지 업데이트", "모델 카탈로그 새로고침"을 실행할 수 있습니다(Pi의 `pi update`). 실행 중인 세션은 지금 버전으로 계속 돌고, 새 버전은 세션을 다시 열면 씁니다. Pi가 직접 업데이트할 수 없는 설치(Nix, 개발용 경로 등)는 그렇다고 알려 줍니다. 설치·제거는 다음 단계입니다.

### 프로바이더

- Pi 관리 창의 "프로바이더" 탭에서 프로바이더별 인증 상태를 확인합니다(`pi auth check`).
- API 키를 등록하거나 지울 수 있습니다. 키는 그 호스트의 `auth.json`에 저장되고, 이 화면에 다시 보이지 않습니다. `!명령` 형식(시크릿 매니저)도 됩니다.
- OAuth를 지원하는 프로바이더는 "OAuth 로그인"을 누르면 아래 터미널 도크에서 `pi`가 열리고 `/login <프로바이더>`가 입력됩니다. 로그인을 마친 뒤 창을 다시 열어 확인합니다.
- 이미 열려 있는 세션은 시작할 때의 모델 목록을 씁니다. 로그인한 프로바이더의 모델이 세션에 없으면 "세션 새로고침" 배너가 나옵니다. 누르면 같은 세션 파일로 Pi를 다시 띄워 대화를 이어 가며 새 모델이 `/model`에 보입니다. 명령 팔레트와 세션 메뉴에서도 할 수 있습니다.
- "모델" 탭에서는 `models.json`의 사용자 정의 프로바이더를 폼으로 편집합니다.
  - 프리셋: Ollama, LM Studio, vLLM, llama.cpp
  - "엔드포인트에서 모델 가져오기": 서버가 가진 모델을 불러옵니다.
  - 폼에 없는 설정은 그대로 남고, 저장 전 내용은 `models.json.bak`에 백업됩니다.

### 설치·다른 버전·제거

- Pi 관리 창의 상태 탭 아래에서 Pi를 설치하거나, 다른 버전으로 바꾸거나(npm 전역 설치만), 제거합니다.
- 버튼을 누르면 실행할 명령이 그대로 보이고, "터미널에서 실행"을 눌러야 내장 터미널에서 실행됩니다.
- Pi를 제거하면 그 호스트에서 실행 중이던 세션을 모두 닫습니다. 대화는 기록에 남아, Pi를 다시 설치하면 이어서 열 수 있습니다.
- macOS·Linux·WSL은 공식 설치기를 먼저 내려받아 내용을 보여준 뒤 실행합니다.
- 세션·설정·자격 증명(`~/.pi/agent`)은 Pi를 제거해도 남습니다. "데이터" 영역에서 언제든 백업할 수 있고, Pi를 제거한 뒤에는 지울 수도 있습니다(두 번 확인, 기본은 백업 후 삭제).

## 리소스

상단의 "리소스" 버튼(또는 명령 팔레트의 "리소스 보기")으로 이 폴더에서 Pi가 불러오는 것을 봅니다. 보고 있는 세션의 폴더, 없으면 입력창의 폴더 기준입니다.

- **컨텍스트**: 시스템 프롬프트에 들어가는 AGENTS.md(데이터 폴더 → 상위 폴더 → 작업 폴더 순)와 SYSTEM.md·APPEND_SYSTEM.md
- **프롬프트·스킬·확장**: 이름·설명·출처(사용자·프로젝트·패키지)와 이름 충돌 같은 문제. 꺼 둔 것은 "꺼짐"으로 표시합니다. 확장은 코드를 실행하지 않고 경로만 찾습니다.
- **패키지**: 설정에 적힌 패키지와 설치 여부
- 로컬·WSL이면 "위치 열기"로 탐색기에서 파일을 봅니다.
- **편집**: AGENTS.md·프롬프트·스킬 항목의 "편집"으로 고치고 Ctrl+S로 저장합니다.
  - 연 뒤에 다른 곳에서 바뀐 파일은 덮어쓰지 않습니다.
  - 저장 전 내용은 `~/.pi-desktop/resource-backups/`에 하나씩 남습니다.
  - 패키지에 든 것과 확장 코드는 고치지 않습니다.
- **삭제**: 사용자·프로젝트 폴더에 직접 둔 프롬프트·스킬·확장의 "삭제" → "정말 삭제"로 지웁니다. 스킬은 폴더째 지웁니다.
  - 바로 지우지 않고 `~/.pi-desktop/resource-backups/deleted/`로 옮깁니다.
  - 패키지에 든 것은 Marketplace에서 패키지를 제거합니다.
  - 열려 있는 세션에서 빼려면 세션을 새로고침하거나 "지금 세션에 반영"을 누릅니다.
- **새로 만들기**: 컨텍스트·프롬프트·스킬·확장 탭 위에서 범위(프로젝트 `.pi/` 또는 사용자)와 이름을 정해 만듭니다.
  - 확장은 템플릿을 고릅니다: 명령(`/이름`), 툴(모델이 부르는 기능), 확인(위험한 bash 명령 전에 묻기), 빈 확장. 만들면 편집기가 열리고, 저장한 뒤 "지금 세션에 반영"이나 Extension Dev Mode로 바로 씁니다.
  - 확장은 TypeScript 파일 하나이며 Pi가 빌드 없이 읽습니다. 사용자 권한으로 실행되므로 믿을 수 있는 코드만 넣으세요. 프로젝트 확장은 그 폴더를 신뢰해야 불러옵니다.
- **새 패키지 만들기**: 패키지 탭의 "새 패키지 만들기"에서 이름·설명·확장 템플릿과 함께 넣을 프롬프트·스킬·확장을 고르면 `~/pi-packages/<이름>`에 Pi 패키지를 만듭니다.
  - 만든 뒤 바로 확장·package.json·README를 편집하고, "이 호스트에 설치"(`pi install <폴더>`)로 설치합니다. 로컬 폴더로 설치하므로 고친 내용이 바로 쓰입니다.
  - 다른 사람과 나누려면 git 저장소에 올리거나(`pi install git:…`) npm에 올립니다(`npm publish`, keywords `pi-package`로 Marketplace에 나옴).
- **내가 만든 패키지**: 패키지 탭에 `~/pi-packages`의 패키지가 설치 여부와 함께 나옵니다. 만든 뒤 바로 설치하지 않았어도 여기서 파일을 골라 편집하고, 설치·설치 해제, 위치 열기, 삭제를 합니다.
  - 삭제는 "정말 삭제"를 한 번 더 눌러야 하며 `~/.pi-desktop/resource-backups/packages/`로 옮깁니다. 설치되어 있으면 먼저 설치 해제를 합니다.
- **다른 호스트로 복사**: 스킬·프롬프트 항목의 "다른 호스트로"로 WSL·SSH 같은 다른 호스트에 복사합니다.
  - 대상 호스트, 범위, 이름을 고르고 파일 목록을 미리 봅니다.
  - 대상 OS에서 돌지 않을 스크립트(Windows의 `.sh`, 리눅스의 `.ps1` 등)는 경고합니다.
  - 같은 이름이 있으면 백업하고 바꿀지 묻습니다.
  - 복사한 뒤 두 사본은 따로 관리됩니다.
- **사용자 AGENTS.md 등 복사**: 컨텍스트 탭에서 데이터 폴더의 AGENTS.md·SYSTEM.md·APPEND_SYSTEM.md를 다른 호스트의 데이터 폴더로 복사합니다.
  - 대상에 이미 있으면 차이를 보여 주고 덮어쓸지 묻습니다.
  - 이전 내용은 대상의 리소스 백업에 남습니다.
- **패키지 다른 호스트에 설치**: 패키지 탭의 "다른 호스트에 설치"로 대상 호스트 터미널에서 같은 소스로 `pi install`을 실행합니다.
  - 로컬 경로 패키지는 옮길 수 없습니다.
  - "일부만 사용" 필터가 있으면 설치가 끝난 뒤 대상에도 같은 필터를 적습니다.
- **모델 프로바이더 복사**: Pi 관리 → 모델에서 프로바이더의 "다른 호스트로"로 models.json 항목을 다른 호스트에 복사합니다.
  - API 키·헤더에 그대로 적힌 값은 옮기지 않습니다. 대상에서 다시 넣어야 합니다. 환경 변수·명령 참조는 그대로 옮깁니다.
  - localhost 주소는 대상 호스트 기준이라는 경고를 보여 줍니다.
  - 대상에 같은 이름이 있으면 바꿀지 묻고, 바꿔도 대상의 키는 남습니다.
  - "복사할 것"에서 모델 하나만 고를 수도 있습니다. 대상에 같은 이름의 프로바이더가 있어야 합니다.
- **설정 편집**: Pi 관리 → 설정 → 편집에서 사용자 settings.json을 폼으로 고칩니다.
  - 그 호스트에 설치된 Pi가 함께 배포한 스키마로 폼을 만들어, Pi 버전에 맞는 항목과 설명이 나옵니다.
  - `defaultProvider`·`defaultModel`은 그 호스트의 Pi가 쓸 수 있는 모델(`pi --list-models`, 로그인한 프로바이더와 models.json)에서 고릅니다. 모델은 고른 프로바이더의 것만 나오고, "직접 입력…"으로 목록에 없는 값을 쓸 수도 있습니다.
  - 바꾼 것을 미리 보고 저장합니다. 비우거나 "기본값"을 고르면 Pi 기본값으로 돌아갑니다. 이전 파일은 `settings.json.bak`에 남습니다.
  - 범위를 "프로젝트"로 바꾸면 그 폴더의 `.pi/settings.json`을 고칩니다. 같은 키는 사용자 설정보다 우선합니다.
  - "JSON"으로 바꾸면 원본을 직접 고치고, 차이를 본 뒤 저장합니다. 그 사이 다른 곳에서 파일이 바뀌었으면 덮어쓰지 않습니다.
- **설정 항목 복사**: Pi 관리 → 설정 탭에서 사용자 settings.json 항목을 골라 다른 호스트에 복사합니다.
  - 항목마다 대상의 지금 값과 견줘 보여 주고, 고른 항목만 바꿉니다. 나머지는 그대로 둡니다.
  - 셸 경로·세션 폴더·프록시처럼 호스트마다 다른 항목은 기본으로 고르지 않습니다.
  - 패키지 목록은 여기서 옮기지 않습니다. 패키지 탭의 "다른 호스트에 설치"를 쓰세요.
- **확장 복사**: 리소스 창 확장 탭의 "다른 호스트로"로 확장 파일이나 폴더를 다른 호스트에 복사합니다.
  - 대상 OS에서 돌지 않을 것 같은 코드(리눅스 대상의 PowerShell, Windows 대상의 `/usr/` 경로 등)를 경고합니다.
  - `node_modules`는 옮기지 않습니다. 의존성이 있으면 대상 폴더에서 `npm install`을 실행하세요.
- **복사 기록**: 다른 호스트에서 복사해 온 스킬·프롬프트·확장·AGENTS.md에는 리소스 창에 "○○에서 복사됨" 배지가 붙습니다.
  - 그 뒤 원본이 바뀌었거나 이 호스트에서 고쳤으면 함께 알려 줍니다. 자동으로 반영하지는 않습니다.
- **호스트 비교**: Pi 관리 → 비교 탭에서 두 호스트의 사용자 스킬·프롬프트·확장·AGENTS.md를 나란히 견줍니다.
  - 한쪽에만 있는 것과 내용이 다른 것을 보여 주고, 그 줄에서 바로 반대편으로 복사합니다.
  - 덮어쓸 때는 대상에서 생기고 바뀌고 사라질 파일(차이)을 보여 주고 한 번 더 묻습니다. 이전 것은 대상의 백업 폴더에 남습니다.
  - 여러 줄을 골라 "고른 n개 → 상대 호스트"로 한꺼번에 복사할 수 있습니다.
- 저장한 뒤 이 폴더의 세션을 보고 있으면 **"지금 세션에 반영"** 버튼으로 세션을 다시 열지 않고 바로 반영합니다.
  - 앱이 Pi에 넣는 작은 확장의 `/desktop:reload`를 씁니다. LLM은 부르지 않습니다.
  - 앱을 업데이트하기 전에 연 세션은 다시 열어야 합니다.
- **프로젝트 신뢰**
  - `.pi/`에 확장·스킬·프롬프트·설정이 있는 폴더를 처음 열면, 신뢰할지 앱이 묻습니다.
  - 선택지는 이번만 / 기억 × 신뢰 / 신뢰 안 함입니다.
  - 신뢰하면 Pi가 프로젝트 확장의 코드를 실행합니다.
  - "기억"은 터미널 pi의 `/trust`와 같은 `~/.pi/agent/trust.json`에 저장됩니다.
  - 리소스 창에서 신뢰 상태를 보고 바꿀 수 있습니다. 바꾼 결정은 새로 여는 세션부터 쓰입니다.
  - AGENTS.md는 신뢰와 상관없이 불러옵니다.

## Marketplace

명령 팔레트의 "Marketplace", 또는 리소스 창 패키지 탭의 "Marketplace에서 패키지 찾기"로 엽니다.

- npm의 Pi 패키지(`pi-package`)를 검색합니다. 다운로드 수와 게시 시각이 함께 나옵니다.
- 상세 화면: README와 보안 요약을 보여 줍니다.
  - README의 HTML은 그리지 않고 글자·링크로 바꿔 보여 줍니다. 외부 이미지(배지·배너)는 대체 글만 나옵니다.
  - 보안 요약은 들어 있는 리소스 종류, 확장 코드 실행 여부, 설치 스크립트, 의존성입니다.
  - **확장이 든 패키지는 Pi 안에서 임의의 코드를 실행합니다.** 설치 전에 저장소를 확인하세요.
- 설치: "터미널에서 설치"를 누르면 그 호스트의 `pi install`이 내장 터미널에서 실행됩니다.
  - 버전 기본값 "최신"은 `pi update`로 갱신됩니다. 특정 버전을 고르면 그 버전에 고정됩니다.
  - 범위는 사용자(모든 폴더) 또는 이 프로젝트(`.pi/settings.json`, 폴더를 신뢰해야 불러옴)입니다.
- 설치한 패키지는 리소스 창의 패키지 탭에서 업데이트하거나 제거합니다.
  - "리소스 고르기"로 패키지에 든 확장·스킬·프롬프트·테마를 하나씩 켜고 끕니다. `pi config`처럼 settings.json의 패키지 필터에 적힙니다.
  - 프로젝트 폴더를 보고 있으면 사용자 패키지를 "이 프로젝트에서만 고르기"로 그 프로젝트에서만 켜고 끕니다. 사용자 설정은 바뀌지 않습니다.
- 설치할 때 "포함할 리소스"에서 종류(확장·스킬·프롬프트 등)를 뺄 수 있습니다. 설치가 끝나면 패키지 필터에 적힙니다.
- 열려 있는 세션에는 "지금 세션에 반영"으로 반영합니다.

**GitHub 스킬·프롬프트 탭**: 패키지가 아닌 저장소에서 스킬 폴더나 프롬프트 하나만 골라 가져옵니다.
- 저장소(`owner/repo`, `owner/repo@브랜치`, 또는 주소)를 입력하거나 예시(`anthropics/skills`, `badlogic/pi-skills`)를 누릅니다.
  - 그 시점의 커밋에 고정해 읽으므로, 본 내용 그대로 가져옵니다.
- 스킬 상세에서 SKILL.md와 함께 든 실행 스크립트를 확인한 뒤, 이름과 범위(사용자 / 이 프로젝트 `.pi/`)를 정해 가져옵니다.
  - 같은 이름이 있으면 덮어쓰지 않습니다.
- 출처(저장소·커밋)는 앱이 기록해 두고, 가져온 항목은 "가져옴"으로 표시됩니다.
- 인증 없이 GitHub API를 쓰므로 시간당 저장소 30개 정도까지 훑을 수 있습니다.
- **가져온 항목 관리**: GitHub 탭의 "가져온 항목 관리"에서 "업데이트·수정 확인"을 누르면 항목마다 상태가 나옵니다.
  - 상태: 이 호스트에서 고친 파일, 원본 새 버전, 원본에서 사라짐, 최신
  - "차이 보기": 이 호스트 내용과 원본 최신을 파일별로 비교합니다.
  - "업데이트": 원본 최신으로 바꿉니다. 고친 내용은 덮어쓰기 전에 한 번 더 묻고, 이전 내용은 `~/.pi-desktop/resource-backups/imports/`에 남깁니다.
  - "제거": 바로 지우지 않고 같은 백업 폴더로 옮깁니다.

  - 터미널을 오른쪽 클릭하면 복사·붙여넣기·모두 선택 메뉴가 나옵니다.

- 개발 환경에서는 `node-pty`(네이티브 모듈)가 설치됩니다. Windows·macOS는 사전 빌드를 쓰고, 그 밖의 플랫폼은 설치 중에 빌드합니다.

## 세션 관리

- 상단 바의 "지금 세션 <폴더>"는 지금 보고 있는 세션의 폴더입니다(마우스를 올리면 전체 경로, Pi 버전, 세션 파일). 그 아래 "새 세션 폴더" 입력줄은 새 세션을 시작할 폴더입니다.
- 실행 중 세션에 마우스를 올리면 ✕가 나타납니다. 누르면 그 세션의 Pi를 끕니다. 대화는 세션 파일에 남으므로, 다시 쓰려면 "기록"에서 누르면 이어서 열립니다.
- 작업 폴더 옆 "새 폴더"로 세션을 시작할 폴더를 만듭니다. 위치(지금 폴더나 홈)와 이름을 정하고 "만들고 새 세션"을 누르면 바로 그 폴더에서 세션을 엽니다. WSL·SSH 호스트에서도 그 안에 만듭니다. "폴더 선택"의 폴더 탐색기에도 "새 폴더"가 있습니다.
- 사이드바 맨 위 검색창으로 실행 중·기록 세션을 이름, 첫 메시지, 폴더로 찾습니다.
- 보고 있는 실행 중 세션에 마우스를 올리면 ✎가 나타나며, 이름을 바꿀 수 있습니다. 바꾼 이름은 탭 제목, 기록, 터미널 pi의 `/resume`에도 보입니다.
- 상단 바의 "HTML 내보내기"는 세션 파일 옆에 HTML을 만들고 탐색기에서 보여줍니다.

## 입력창

- `Enter` 보내기, `Shift+Enter` 줄바꿈. Pi가 일하는 중에 `Enter`를 누르면 Follow-up으로 보냅니다.
- `↑`·`↓`: 이전에 보낸 입력 불러오기. 쓰던 초안은 세션별로 저장되어 앱을 다시 열어도 남습니다.
- `/`: 명령 자동완성 (`Tab`·`Enter`로 채우기, `Esc`로 닫기)
  - Pi가 알려 주는 프롬프트 템플릿, 스킬, 확장 명령
  - 터미널 pi의 기본 명령: `/model`, `/thinking`, `/compact`, `/new`, `/resume`, `/name`, `/session`, `/tree`, `/fork`, `/clone`, `/copy`, `/export`, `/reload`, `/settings`, `/login`, `/logout` 등. Pi RPC는 이것들을 알려 주지 않아 앱이 같은 기능(모델 선택, 트리, Pi 관리 등)으로 처리합니다. 앱에 없는 명령(`/share` 등)은 안내만 합니다.
- `@`: 작업 폴더의 파일·폴더 찾아 넣기. git 저장소면 `.gitignore`를 따릅니다. 폴더를 고르면 안으로 이어서 고를 수 있습니다. 경로만 넣고, 모델이 필요하면 직접 읽습니다(터미널 pi와 같음).
- 이미지: 입력창에 붙여넣거나(`Ctrl+V`) 끌어 놓으면 질문과 함께 보냅니다 (PNG·JPEG·GIF·WebP). 지금 모델이 이미지를 받지 않으면 안내가 나옵니다.
- `!명령`: 셸 명령을 실행하고 결과를 다음 질문의 컨텍스트에 넣습니다. `!!명령`은 컨텍스트에 넣지 않습니다. 실행 중인 명령은 카드의 "멈춤"으로 멈춥니다.
- Windows에서는 bash 명령(모델의 bash 툴, `!명령`) 앞에 `chcp.com 65001`을 붙여 기본 명령(findstr·tasklist 등)의 출력이 깨지지 않게 합니다. 이때 Windows 기본 명령의 안내 문구는 영어로 나옵니다. Pi 설정 `shellCommandPrefix`를 직접 정했으면 붙이지 않습니다.
- Pi가 일하는 중에 보낸 Steer·Follow-up은 입력창 위에 "대기 중"으로 보입니다. "비우고 입력창으로"를 누르거나 "중단"하면 대기 중인 글이 입력창으로 돌아옵니다.
- 응답 오류로 자동 재시도 중이면 배너에서 "재시도 취소"를 누를 수 있습니다. 결국 실패하면 "다시 보내기"로 질문을 입력창에 다시 채웁니다.

## 터미널 pi(TUI)와 함께 쓰기

같은 세션 파일에 GUI와 TUI가 동시에 쓰면 기록이 꼬일 수 있어 다음처럼 동작합니다.

- **TUI가 쓰는 세션을 GUI에서 열 때**: 기록에서 고른 세션이 최근 2분 안에 수정됐고 GUI가 쓰는 파일이 아니면, 바로 열지 않고 고르게 합니다.
  - 읽기 전용으로 따라가기: 파일이 바뀔 때마다 화면이 갱신됩니다 (완료된 메시지 단위)
  - 분기해서 새 세션으로 이어 쓰기: 원래 파일은 그대로 두고 새 파일에서 이어 갑니다
  - 그래도 이 파일로 열기: TUI를 이미 닫았다면 이걸 고르면 됩니다
- **GUI 세션을 TUI로 넘길 때**: 상단의 "TUI에서 열기"를 누르면 GUI 쪽 Pi를 닫고 터미널 명령을 복사합니다. GUI는 그 파일을 읽기 전용으로 계속 보여줍니다. 아직 메시지가 없는 세션은 파일이 없으므로 `pi --session-id <id>` 명령을 복사합니다.
- **TUI를 끝내고 GUI로 돌아올 때**: 읽기 전용 배너의 "GUI에서 이어 쓰기"를 누르면 같은 세션 파일을 GUI에서 다시 엽니다. 배너를 닫았다면 "기록"에서 그 세션을 눌러도 됩니다(최근 2분 안에 바뀐 파일이면 "그래도 이 파일로 열기"를 고릅니다). TUI를 끄지 않은 채 GUI에서도 쓰려면 "분기해서 이어 쓰기"를 쓰세요.
- **GUI가 쓰는 세션에 TUI가 끼어들면**: 다른 프로그램이 같은 파일에 쓴 것을 감지해 입력을 잠그고 고르게 합니다.
  - 닫고 따라가기: GUI 쪽 Pi를 닫고 읽기 전용으로 따라갑니다
  - 복제해서 계속: GUI 쪽 대화를 새 파일로 복제해 따로 이어 갑니다
  - 무시하고 계속: 그대로 씁니다 (기록이 섞일 수 있음)

## 세션 복구 동작

- **앱을 닫았다 열거나 연결이 끊겼다 붙으면**: 데몬의 이벤트 저널에서 놓친 부분을 재생해 이어서 보여줍니다.
- **저널 앞부분이 잘렸으면** (세션당 최근 1만 이벤트만 보관): Pi의 `get_messages`로 대화 전체를 받아 화면을 다시 만듭니다.
- **데몬이 재시작되었거나 Pi가 종료되면**: 대화는 화면에 남기고 "다시 열기"를 보여줍니다. 누르면 같은 Pi 세션 파일로 다시 열어 대화를 이어 갑니다. 진행 중이던 턴은 이어지지 않습니다.
- **다른 PC의 앱이 같은 원격 세션에 붙으면**: 입력은 한 앱만 할 수 있습니다. 나중에 붙은 앱은 대화를 실시간으로 보기만 하고, "제어 가져오기"를 누르면 입력 권한이 넘어옵니다 (원래 앱은 읽기 전용이 됩니다). 입력하던 앱을 닫으면 남은 앱이 바로 입력할 수 있습니다.
- **Pi Desktop을 또 열면** (바탕화면 아이콘을 다시 누르거나 다른 앱이 실행 파일을 열면): 설치본은 창을 하나만 띄웁니다. 새 창 대신 이미 떠 있는 창을 앞으로 가져옵니다 (최소화돼 있으면 복원). 개발 실행(`npm run dev`, `dev:mock`)은 막지 않습니다.
- **앱이 새 Host Agent를 가져왔는데 예전 데몬이 떠 있으면**: 실행 중인 세션이 없을 때 데몬을 알아서 바꿉니다. 세션이 있으면 그대로 쓰면서 "Agent 업데이트 대기" 배지를 띄우고, 세션이 모두 끝나면 바꿉니다. 배지를 눌러 지금 바꿀 수도 있습니다 (그때 실행 중인 세션은 "다시 열기"로 이어 갑니다).

## 알려진 한계

- 디자인 시스템은 아직 없습니다.
- 탭을 끌어 순서를 바꾸거나 새 창으로 떼어 내는 기능은 아직 없습니다.
- 세션 트리에서는 분기(fork)와 복제(clone)만 됩니다. TUI의 `/tree`처럼 같은 세션 안에서 다른 갈래로 옮겨 가는 명령은 Pi RPC에 없습니다.
- SSH는 `~/.ssh/config`의 호스트를 아직 자동으로 가져오지 않습니다. 대상에 Host 이름을 직접 적으면 그 설정을 씁니다.
- 앱과 Host Agent 데몬은 연결할 때 사용자만 읽을 수 있는 토큰(`~/.pi-desktop/run/agentd.token`)으로 서로를 확인합니다. 그래서 이전 버전 앱은 새 데몬에 붙지 못할 수 있으니 함께 업데이트하세요. Windows에서 예전 데몬이 떠 있으면 앱이 한 번 끄고 새 데몬으로 바꿉니다. 그때 실행 중이던 세션은 끝나며, 기록에서 다시 열면 됩니다.
- 앱을 업데이트해도 세션이 돌고 있으면 예전 Host Agent를 계속 씁니다(상단 바 "Agent 업데이트 대기"). 이때 새 기능(확장·패키지 만들기 등)이 예전 Agent에 거절되면 그 이유와 함께 "지금 바꾸기"로 Agent를 바꾸라는 안내가 나옵니다.
- 설치본은 `PI_DESKTOP_REMOTE_DEBUG_PORT` 환경 변수를 쓰지 않습니다. 설치본을 CDP로 검증하려면 실행 인자 `--remote-debugging-port=9333`을 주세요.
- Windows에서 데몬은 WMI로 띄웁니다 (앱 핸들 상속 방지). 문제를 조사할 때는 `PI_DESKTOP_DAEMON_SPAWN=direct`로 예전 방식을 쓸 수 있습니다.
