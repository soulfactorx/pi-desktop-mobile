# Pi Desktop Agent

Pi를 엔진으로 쓰는 데스크톱 에이전트입니다. Pi Desktop과는 **별도의 앱**이며, 기능은 Pi 패키지인
[`packages/agent-kit`](../../packages/agent-kit)(확장·스킬)으로 구현합니다.

- 설계: [docs/DESIGN-AGENT.md](../../docs/DESIGN-AGENT.md)
- 현재 단계: P0~P4(골격·승인·로컬 모델·기본 기능·백그라운드)를 마치고 P5(네트워크·피어 작업·권한 상승)를 진행 중이며, `agent-v*` 릴리스로 배포 중. 단계별 메모는 설계 §5
- 남은 확인: qwen3.5:9b 로컬 모델 실측(설계 §7 절차), 중계 서버는 설계만(설계 §8)

## 화면

- **왼쪽 사이드바**: "+ 새 대화"(마지막 폴더, Ctrl+N)와 📁 ▾(최근 폴더·홈·다른 폴더에서 새 대화). 열린 대화는 **작업 폴더별로 묶여** 보이고, 두 번 누르거나 머리의 ✎·F2로 이름을 바꿉니다 (Pi 세션 이름이라 Pi Desktop·TUI에도 같은 이름).
- **대화 중 폴더 바꾸기**: 대화 머리의 `📁 경로 ▾`에서 다른 폴더를 고르면, 지금까지의 대화를 가지고 그 폴더에서 이어 갑니다 (Pi 세션 분기, 원래 대화는 남음).
- **메뉴바**
  - 파일: 새 대화(Ctrl+N) · 폴더를 골라 새 대화(Ctrl+O) · 대화 이름 바꾸기(F2) · 대화 닫기
  - 보기: 대화(Ctrl+1) · 작업·예약(Ctrl+2) · 지식베이스(Ctrl+3) · 스킬(Ctrl+9) · 승인(Ctrl+4) · 사용량(Ctrl+5) · 지난 대화(Ctrl+6) · 웹 검색·MCP(Ctrl+7) · 네트워크(Ctrl+8) · 설정(Ctrl+,)
  - 도움말: 업데이트 확인 · 릴리스 페이지 · 정보
- **대화**: 빈 대화에 할 수 있는 일 예시. 머리에서 이름·작업 폴더·이 대화의 모델을 봅니다.
- **작업·예약 / 승인 / 설정**: 맡긴 작업·예약 결과, "항상 허용" 규칙·최근 판단, Pi 상태·업데이트.
- **네트워크**: 다른 사람의 Pi Desktop Agent와 연결합니다. "받기"를 켜고(기본 꺼짐) 내 카드(이름·소개·잘하는 것)를 적은 뒤("기억으로 초안 만들기"로 채우고 고쳐도 됩니다), 상대 주소로 카드를 보고 페어링을 요청합니다. 상대가 승인하면 피어가 되고, 대화에서 "○○에게 물어봐"라고 하면 승인을 받은 뒤 묻습니다. 상대의 질문에는 도구 없이 내 기억(선호 제외)과 일반 지식으로만 답하고, 피어마다 질문 받기와 하루 상한을 정합니다. 같은 네트워크(사내망·VPN)에서만 닿습니다.
- **피어에게 작업 맡기기**: 대화에서 "○○에게 맡겨"라고 하면 승인을 받은 뒤 상대에게 보냅니다. 상대가 폴더를 골라 승인하면 상대 PC의 그 폴더 안에서만 작업하고(명령 실행·웹 없음), 끝나면 결과가 [작업 알림]으로 들어옵니다. 받은 쪽은 OS 알림과 네트워크 화면 맨 위의 "들어온 작업 요청"에서 승인·거절하고, 피어마다 "작업 받기"를 끌 수 있습니다.
- **관리자 권한 실행** (설정, 기본 꺼짐): 켜면 에이전트가 관리자 권한이 필요한 작업(패키지 설치, 서비스 재시작 등)을 요청할 수 있습니다. 매번 실행될 명령 그대로 승인을 받고, 비밀번호는 OS 인증 창(UAC 등)이 직접 받습니다. 예약·백그라운드 작업에서는 쓸 수 없습니다.
- **웹 검색·MCP**: 웹 검색 서버를 골라 넣습니다. Exa는 키 없이 바로, Brave·Tavily는 API 키를 넣으면 됩니다(Node.js 필요). 이 앱의 mcp.json에 있는 서버를 켜고 끄거나 빼고, "연결 확인"으로 `pi mcp list` 결과를 봅니다. 새 대화부터 적용됩니다.
- **첨부**: "파일 첨부"로 고른 문서(.txt·.md·.docx·.pdf 등)는 경로가 메시지에 들어가고 에이전트가 필요한 만큼 읽습니다. 이미지(png·jpeg·gif·webp, 5MB까지)는 미리 보기로 붙어 메시지와 함께 갑니다. 화면 캡처를 입력창에 붙여 넣어도 됩니다. 이미지를 못 보는 모델이면 경로만 붙입니다.
- **지난 대화**: 파일 > 지난 대화 열기…(Ctrl+Shift+O) 또는 사이드바 아래 "지난 대화…". 닫은 대화를 이름·첫 메시지·폴더로 거르고, Enter로 대화 내용까지 찾습니다. 누르면 그 대화를 이어서 엽니다 (이미 열려 있으면 그 대화로 이동). 📦로 목록에서 숨기면(아카이브) "아카이브"에서 되돌리고, 🗑로 지우면 휴지통으로 옮겨져 "휴지통"에서 되살리거나 정말 지울 수 있습니다.
- **사용량**: 오늘·7일·30일·12개월의 토큰·비용(추정)·호출 수를 막대 차트와 모델별·쓰임새별 표로 봅니다. 이 앱의 대화와, 세션에 남지 않는 기억 추출·문서 처리·백그라운드 작업을 함께 셉니다.
- **지식베이스**: 에이전트가 대화에서 남기거나 직접 쓴 지식을 사용자·요구사항·교훈·참조로 나눠 관리합니다. 고정 항목은 늘, 나머지는 제목 목록과 요청에 관련된 것의 본문이 대화에 실립니다. 찾기·종류·태그로 거르고, 여러 개 골라 보관·고정·태그·합치기·지우기를 합니다. 점검 대기함은 중복 의심, 오래 안 쓰인 것, "재발 방지"가 없는 교훈, 도구로 확인하지 않은 대화에서 나온 것을 모아 보여 줍니다. 통계·주입 미리보기와 Markdown 내보내기도 있습니다. 대화가 끝나면 자동으로 남기는 기능은 이 화면에서 끌 수 있습니다. 바깥에 보이면 안 되는 항목에는 `공유제외` 태그를 붙이세요.
- **스킬**: 되풀이하는 작업 방법을 Pi 스킬(SKILL.md)로 둡니다. 스킬 화면에서 이름·설명·지시를 적어 만들고 고치며, "대화에서 쓰기"를 누르면 입력창에 `/skill:이름`이 채워집니다. 모델은 설명을 보고 필요할 때 알아서 읽습니다(끌 수 있음). 대화에서 "이걸 스킬로 만들어"라고 해도 승인을 받고 저장합니다. 바꾼 스킬은 새 대화부터 쓰입니다.

**Pi 관리(설치·로그인·API 키·프로바이더·모델)는 Pi Desktop에서 합니다.** Pi나 쓸 수 있는 모델이 없으면 화면 위에 안내가 뜨고 Pi Desktop을 열거나 설치할 수 있습니다. Pi Desktop이 이미 떠 있으면 새로 띄우지 않고 그 창으로 갑니다.

**자동 업데이트**: v0.1.2부터 앱을 켜고 20초 뒤와 6시간마다 새 버전을 확인합니다. 새 버전이 있으면 사이드바 아래에 배지가 뜨고, 묻기 전에는 내려받거나 설치하지 않습니다 (Windows·AppImage는 설치, macOS·deb는 릴리스 페이지를 엽니다).

**호스트 (WSL·SSH)**: 설정의 "호스트"에서 대화를 돌릴 컴퓨터를 고릅니다 (로컬, WSL 배포판, 등록한 SSH 호스트). 원격을 고르면 그 호스트에 Host Agent와 agent-kit을 올리고(`~/.pi-desktop-agent/agent/`, `kits/<해시>/`), 그 호스트의 Pi와 `~/.pi-desktop-agent`로 대화합니다. 대화·지난 대화·휴지통·아카이브·예약 세션은 그 호스트에서 돕니다. 폴더는 데몬으로 그 호스트의 폴더를 훑어 고릅니다. 기억·작업·스킬·승인·사용량·웹 검색·네트워크 화면과 대화 내용 검색은 아직 이 PC의 것만 다룹니다 (다음 단계 D4). SSH는 키 인증만 씁니다.

## 구조

```
apps/agent/            이 앱 (main · preload · React 렌더러)
packages/agent-kit     에이전트 기능 묶음 (Pi 패키지: 확장·스킬, 터미널 pi에도 설치 가능)
packages/host-agent    Pi Desktop과 같은 Host Agent (데몬 홈만 따로 씀)
packages/pi-isolation  앱 홈의 데이터만 Pi에 올리는 실행 옵션과 MCP·문맥 파일 확장 (Mate와 함께 씀)
```

- 앱 홈은 `~/.pi-desktop-agent`입니다. Host Agent 데몬, 세션(`sessions/`), 스킬(`skills/`), 프롬프트(`prompts/`), MCP(`mcp.json`), 사용자 지침(`AGENTS.md`), agent-kit 상태(`data/`)가 모두 여기 있습니다.
- Pi의 로그인·모델·설정(`~/.pi/agent`)만 Pi Desktop·터미널 pi와 함께 씁니다. 세션·스킬·확장·MCP는 섞이지 않습니다 ([데이터 경계](../../docs/DESIGN-APPS.md)).
- 세션을 열 때 `--session-dir`·`-ns --skill`·`-np --prompt-template`·`-ne -e <agent-kit·pi-isolation 확장>`·`-nc`를 붙입니다. 사용자 `settings.json`에는 기록하지 않습니다.
- 예전 위치(`~/.pi/agent/pi-desktop-agent/`, `~/.pi/agent/sessions`의 Agent 대화)는 읽지도 지우지도 않습니다. 새 폴더에서 빈 상태로 시작합니다.

## 실행

API 키 없이 mock LLM으로 실행합니다 (포트 18912, Pi Desktop의 dev:mock과 동시에 띄울 수 있음).

```bash
npm run dev:mock -w @pi-desktop/agent
```

- 프롬프트 예: `안녕` → echo, `read:package.json` → read 툴 호출(묻지 않음), `bash:echo hi` → 승인 화면, `/agent:status` → agent-kit 버전 알림
- 데몬 홈은 저장소의 `.dev/agent-home`, Pi 설정은 `.dev/pi-agent`로 격리됩니다.

설치된 Pi로 실행할 때는 `npm run dev -w @pi-desktop/agent`를 씁니다.

## 설치 파일과 릴리스

```bash
npm run dist -w @pi-desktop/agent
```

지금 OS용 설치 파일을 `apps/agent/release/`에 만듭니다 (올리지 않음). 설치본은 Host Agent 번들과 agent-kit 소스를 리소스로 싣고,
**대상 PC에 설치된 Pi**(`npm install -g @earendil-works/pi-coding-agent`)를 씁니다.

릴리스는 `agent-v`로 시작하는 태그를 올리면 `.github/workflows/release-agent.yml`이 세 OS에서 만들어
이 저장소의 GitHub Releases에 올립니다. **Latest로 표시하지 않아** Pi Desktop(`v*`)의 자동 업데이트와 섞이지 않습니다 (Pi Desktop Mate의 `mate-v*`와 같은 방식, 설계 §0).
릴리스에는 자동 업데이트용 latest.yml·latest-linux.yml·blockmap도 함께 올라갑니다.

```bash
git tag -a agent-v0.1.0 -m "Pi Desktop Agent v0.1.0"
```

```bash
git push origin agent-v0.1.0
```

Actions 탭에서 "Release Agent"를 손으로 돌리면 만들기만 하고 올리지 않습니다. 코드 서명은 하지 않습니다 ([루트 README의 "코드 서명"](../../README.md#코드-서명)).
